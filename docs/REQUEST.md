## 목적과 가치

바야흐로 AI 시대. 사실 AI 시대가 아니라도 새 프로젝트를 시작할 때에는 늘 많은 문제가 있어왔고. 그래서 이 modern react starter 를 만들게 되었습니다.

### 코드 모범 사례의 확립

인간이나 AI나 이미 모범 사례가 확립되고 나면, 좋은 패턴을 일관되게 반복하면 많은 에러도 사라지고 코드 베이스를 이해하기도 쉬워집니다.

하지만 모범 사례가 없으면 AI 나 인간이나 나쁜 패턴을 반복하고 실수하고 이미 한 시행착오를 똑같이 반복하게 됩니다. 예를 들면 다음과 같습니다.

1. 파편화된 vi.mock 처럼 추적할 수 없는 의존성 갈아끼우기 패턴
2. 컴포넌트 라이브러리 대신 그때그때 파편화되는 스타일
3. E2E 테스트에서 DB를 호출하며 추상화가 누출
4. 순수 함수, 순수한 로직 대신 사소한 로직도 DB 등 수 많은 의존성 없이는 테스트가 불가능해짐
5. ...

그 외에도 react, tanstack start, tanstack router, tanstack query, vite, jotai, bunja, valibot, standard schema, temporal, pandacss와 arkui, elysia, drizzle-orm, postgres와 pglite, better auth, react-hook-form 처럼 이미 제가 검증하고 만들어온 프레임워크와 라이브러리의 조합이 있고. 그 조합은 어떤 식으로 역할을 나누고 개발해야 하는지 모범 사례가 없으면 매번 query option 은 어떻게 관리할지부터 다시 결정해야하게 됩니다.

### 표준적 개발 도구의 셋업

oxfmx, oxlint, typescript, vitest, browser mode, storybook, jscpd, nose (https://github.com/corca-ai/nose) ... 이처럼 많은 개발 도구를 셋업해야 하고. 이러한 도구들을 특정 프레임워크에 특정 스타일링 라이브러리 등과 조합하는 건 더 귀찮은 일입니다. 뭔가를 만들고 싶은데 이런 셋업을 하다가 시간이 다 가는 경우도 많지요.

### AI가 인간을 증강하는 개발 흐름 확립

사람들을 다 제멋대로의 방식으로 개발을 합니다. 요즘은 인간은 코드를 보지 않는 것도 유행을 하지요. 하지만 세상에는 모든 코드를 다 읽는 접근과 전혀 읽지 않는 2분법으로 굴러가지 않습니다.

그래서 잘 정련된 개발 흐름(development workflow)이 필요합니다. matt pocock 씨의 skill을 토대로 해서, 정련된 개발 흐름을 통해 좋은 코드를 만들고요. 개발 과정을 회고하고 이를 통해 배운 것이 좋은 AGENTS.md 와 SKILL.md 에 반영되고 개선되야 합니다. 그렇게 결정들이 누적되면서 처음부터 결정할 일이 줄어들고, 이미 한 결정도 돌아보고 새로 결정하게 됩니다.

더 나아가 우리가 개선이라 생각한 SKILL.md 등이 좋은 코드를 만드는지. branch 등의 기능을 잘 활용해서. 똑같은 것을 과거로 돌려서 다시 만들어보고 비교해봄으로서 실험하고 evaluation 하고 검증해야 합니다. 또 그러려면 sub agent를 잘 활용해서 작은 일을 맡겨보는 것도 필요합니다. 작아야 실험을 많이 해볼 수 있으니까요.

이 과정에서 사람은 AI 덕분에 배우고, AI는 인간 덕분에 더 잘 하게 되는 좋은 협력 관계가 성립해야 합니다.
