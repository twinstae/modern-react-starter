# TICKET-00007: 결과 화면 — 상태 문장, 추천 서랍, 주인에게 보여 주기

- 스펙: [TECH_SPEC](TECH_SPEC.md) §5.3 결과, I-8, I-9, R-11, C-2
- Blocked by: TICKET-00004, TICKET-00006
- Status: done

## 만들 것

- `ResultScreen`(표시용): TICKET-00004의 결과 view model을 받는다.
  ① "토끼 님에게는…" 1순위 상태 문장(가장 크게) ② 2순위 상태 문장("함께") ③ 추천 서랍 카드(서랍 이름, 서랍 표시, 인용 + 권하는 이유) ④ "책방 주인에게 이 화면을 보여 주세요"와 주인 확인 버튼 ⑤ 다시 해 보기(작게).
- 라우트: 마지막 답 뒤 결과로 간다. 주인 확인 버튼은 TICKET-00012의 잠금으로 이어진다(그 전까지는 콜백만).

## 알아야 할 것

- 이 화면의 목적은 "내가 지금 이런 질문 앞에 있구나". 위 60%는 문장, 아래 40%에 서랍 카드와 안내.
- 서랍 속 책 제목은 보이지 않는다(C-2). 서랍을 여는 순간을 남긴다.
- 점수, 서랍 코드, 순위 숫자, 퍼센트를 보이지 않는다(I-9).
- 손님이 주인에게 태블릿을 들고 가거나 주인이 다가오는 상황이다. 멀리서도 서랍 표시가 보이게 크게 둔다.
- 마지막 답 → 결과 사이의 짧은 전환은 [탐색]. 넣는다면 `prefers-reduced-motion`을 따른다.

- [x] 추천 서랍 카드에 인용된 답과 권하는 이유가 보인다(컴포넌트, I-8).

## 작업하며 배운 것

- 권하는 이유는 책이 아니라 서랍에 붙였다. 그래야 결과 화면이 서가를 모른 채 `CustomerCuration`
  하나로 그려지고, 책별 이유는 TICKET-00012의 서랍 속 책 화면에 그대로 남는다.
- 서랍 표시(`mark`)는 TICKET-00006에서 손님 묶음에서 뺐지만, 스펙 §5.3의 결과 카드가 표시를
  보여 주므로 공개 묶음에 다시 넣었다. 손님에게 보이는 것은 코드(B1~B7)가 아니라 사람이 읽는
  번호·열쇠 이름이다.
- 7개 서랍 스토리는 시드 질문 세트에 "그 서랍 문항만 5, 나머지는 1"로 답해 만든 실제
  `curate` 결과다. 가장 긴 스토리는 문장과 이유 길이의 합으로 골라, 태블릿 레이아웃을
  실제 데이터로 확인한다.
- 결과 화면의 주인 확인 안내는 라우트가 소유한다(`ownerCheckNotice` prop). 컴포넌트는
  표시만 하고, TICKET-00012가 실제 PIN으로 바꿀 때 문구와 상태를 라우트에서 걷어낸다.
- siheom `query.status`는 접근성 이름으로 찾는다. 안내 문단에 `role="status"`만 두면
  이름이 비어 잡히지 않아 `aria-label="주인 확인 안내"`를 붙였다.
- Storybook의 `#storybook-root` 16px 패딩 때문에 Playwright로 body 스크롤을 재면 앱과
  무관한 32px 넘침이 보였다. 레이아웃은 `main`의 높이와 내부 섹션으로 확인해야 했다.
