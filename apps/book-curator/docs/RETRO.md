# 회고 기록

티켓마다 "다음 에이전트가 더 잘 일하게" 바꾼 것을 남긴다. 결론만 적고, 이미 반영한 것은
`AGENT_PLAYBOOK.md`에만 둔다. 여기에는 왜 바꿨는지와 다음에 확인할 것을 적는다.

## 00001 — 앱 뼈대

**관찰**

- 루트 `bun run ci`가 book-curator와 무관한 `simple-event` 타입 오류와 `solo-quest` lint
  오류로 실패한다. 티켓 인수 조건을 앱 밖의 실패가 막았다.
- 에이전트가 앱 단독 dev/Storybook 확인은 잘했지만, "루트 dev"와 "앱 단독 dev"의 차이를
  스스로 판단해 기록해야 했다. 포트와 확인 방법을 더 명시할 필요가 있었다.
- Vite+ type-aware lint, Storybook 10 viewport, fast-check v4 함정은 티켓 문서에 없었다.
  해결책은 티켓의 "작업하며 배운 것"에만 남아 다음 에이전트가 다시 만날 수 있었다.

**반영**

- `apps/book-curator`에 `check` 스크립트를 더했다. 루트 CI 대신 앱 범위 lint·format·
  typecheck·test를 한 번에 돌리는 커밋 전 게이트다.
- playbook에 루트 CI를 쓰지 않는 이유와 `storybook-static`을 커밋하지 않는 규칙을 적었다.
- 다음 회고 때 확인할 것: 에이전트가 `check`를 실제로 돌렸는지, 루트 CI 실패를 다시
  조사하느라 시간을 썼는지.

## 00002 — 큐레이션 코어

**관찰**

- `check` 게이트를 실제로 썼고, 루트 CI를 다시 조사하지 않았다. 00001의 개선이 먹혔다.
- 코어가 7개 파일로 늘었지만 다음 티켓이 함수 이름·오류·0점 규칙을 파일마다 다시
  찾아야 한다. 티켓 문서의 "작업하며 배운 것"은 구현자에게는 남지만 다음 에이전트의
  진입점은 아니다.
- 테스트 46개 중 컴포넌트는 1개뿐이다. 순수 계산을 컴포넌트로 올리지 않은 판단은 좋았다.

**반영**

- playbook에 "이미 있는 코어" 절을 더해 공개 함수, 오류, 0점·5의 수·비슷함 규칙을
  한곳에 적었다. 다음 티켓은 파일을 다시 읽지 않고 여기서 시작한다.
- 다음 회고 때 확인할 것: 다음 에이전트가 기존 코어를 다시 만들거나 이름을 바꾸지
  않는지, 새 결정을 playbook에 반영해야 하는지.

## 00003 — 공개 점검기와 시드

**관찰**

- 사람이 정할 것(시드 문구, 기준 응답, 문항 수, 반대 문항, 동점 순서, 10~18% 기준)이
  `SEED-QUESTIONS.md`와 티켓 문서에 흩어졌다. 사용자가 돌아왔을 때 여러 파일을 읽어야 한다.
- 시드가 게이트를 통과했지만 B6가 17.9%로 상한에 붙어 있다. 다음 티켓이 문구나 순서를
  조금 바꾸면 바로 실패할 수 있다. 이 사실이 "작업하며 배운 것"에만 있었다.
- 에이전트가 스스로 playbook에 코어 진입점을 더했다(좋은 행동). 회고를 기다리지 않아도
  다음 사람이 읽을 곳을 남기는 습관은 유지한다.

**반영**

- `docs/OPEN-QUESTIONS.md`를 만들었다. 사람이 정할 것과 환경 이슈를 한곳에 모으고,
  세부 근거는 `SEED-QUESTIONS.md`를 가리킨다. playbook의 "막히면 여기에"와 연결했다.
- 다음 회고 때 확인할 것: 시드가 깨졌을 때 에이전트가 상수를 풀지 않고 결정 요청을
  남기는지, OPEN-QUESTIONS가 중복으로 불어나지 않는지.
