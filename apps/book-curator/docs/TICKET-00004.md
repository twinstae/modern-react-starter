# TICKET-00004: 상태 문장, 한국어 조사, 별명, 답 인용

- 스펙: [TECH_SPEC](TECH_SPEC.md) I-8, I-10, R-11
- Blocked by: TICKET-00002
- Status: done

## 만들 것

- 상태 문장 템플릿: 질문 세트의 공통 템플릿(예: "{nickname} 님에게는 지금 {drawer}이/가 필요한 상태입니다")과 서랍별 고유 문장. 고유 문장이 있으면 그것을 쓴다.
- 조사 처리: 서랍 이름의 받침에 맞춰 이/가, 을/를, 은/는, 와/과, (으)로를 고른다. 템플릿에서 조사를 적는 문법을 정하고, 모르는 자리표시는 오류로 돌려준다.
- 인용: 추천 서랍에 가장 크게 기여한 손님의 답을 골라, 직접 인용 문형으로 권하는 이유 앞에 붙인다. 문항형은 문항 문장("'…'에 그렇다고 답하신"), 선택형은 선택지 문장. 문형은 질문 세트에 담겨 관리자가 고칠 수 있다.
- `curate(version, answers, nickname)` → 손님 결과 view model(상태 문장 둘, 추천 서랍 카드). 점수와 서랍 코드가 없다(I-9).

## 알아야 할 것

- 별명 뒤에는 늘 "님"이 붙으므로 별명에는 조사 처리가 필요 없다. 별명의 길이·문자 규칙은 스키마 하나로 정한다.
- 기계적으로 끼워 넣은 티가 나지 않는 것이 목표다. 직접 인용은 문장 끝말이 무엇이든 문법이 깨지지 않는다.
- 문항형에서 "기여가 큰 답"은 높게 답한 그 서랍 문항이다(반대 문항은 낮게 답한 것). 인용할 답이 없을 수는 없는지 속성으로 확인한다.
- 실제 문장이 어떻게 읽히는지는 결과 화면 스토리(TICKET-00007)에서 주인과 함께 읽는다.

- [x] 받침 있는 이름("…책")과 없는 이름, ㄹ 받침 + (으)로, 한글이 아닌 끝의 예시가 통과한다.
- [x] 임의의 한글 음절로 끝나는 이름에서 조사가 받침 규칙과 맞다(속성, I-10).
- [x] 별명이 상태 문장에 "토끼 님"으로 들어간다(예시).
- [x] 서랍별 고유 문장이 있으면 템플릿 대신 쓰인다(예시).
- [x] 모르는 자리표시가 든 템플릿은 이유와 함께 거부된다(예시).
- [x] 무작위 질문 세트·답에서 인용된 답은 늘 손님이 실제로 한 답이고 추천 서랍에 기여했다(속성, I-8).
- [x] 결과 view model 타입에 점수와 서랍 코드가 없다(타입).

## 작업하며 배운 것

- 조사는 마지막 글자의 `(코드 - 0xAC00) % 28`만 본다. ㄹ 받침은 `8`이라
  `(으)로`에서 따로 처리해야 한다. 한글이 아닌 글자로 끝나면 받침 없음으로 두고
  `Book가`처럼 붙인다. 이름 끝 공백은 조사를 붙이기 전에 지운다.
- 상태 문장 템플릿은 `{nickname}`, `{drawer}`, `{drawer:이/가}`만 받는다. 별명은
  자리표시가 아니라 스키마가 "이름 님" 꼴을 만든다. 템플릿에 ` 님`이 이미 있으면
  한 번만 남겨서 `{nickname} 님`과 `{nickname}` 둘 다 같은 문장이 된다.
- 인용은 `DrawerScores.contributions`를 그대로 쓴다. 문항형은 뒤집은 유효값,
  선택형은 가중치가 이미 들어 있어 채점기마다 인용 규칙을 다시 만들지 않는다.
  0·음수 기여는 권하는 이유가 아니므로 인용 후보에서 뺀다.
- 질문 세트의 새 문장 필드는 optional로 받고 파싱·DTO에서 기본값과 `statement: null`로
  정규화한다. 소비자는 "필드가 있는지"를 분기하지 않는다.
- `curate`는 순위·점수·서랍 정의를 내부에 두고, 손님 view model은 문장 다섯 개만
  노출한다. 주인 확인(TICKET-00005)은 내부 값을 쓰고 화면은 손님 view model을 쓴다.
