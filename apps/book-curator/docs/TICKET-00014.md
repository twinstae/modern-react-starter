# TICKET-00014: 서버 없이 태블릿 안에서만 도는 PWA

- 스펙: [ADR 0006](adr/0006-local-first-indexeddb-pwa.md), TECH_SPEC I-11·I-12·I-15·I-16
- Status: done (2026-11-23). 실제 iPad·안드로이드 태블릿 설치 확인은 사람이 한다

## 만들 것

- IndexedDB 저장소 다섯 개. 메모리 구현과 같은 계약 테스트를 통과한다.
- PIN·운영 비밀번호 해시를 Web Crypto로. 주인 토큰을 없앤다.
- 운영 비밀번호: 처음 열 때 정하고, 다음부터 그 비밀번호로 운영 화면을 연다.
- 라우트가 HTTP 대신 기기 저장소 위의 유스케이스를 부른다. 빈 기기는 시드 서랍을 공개한다.
- 운영 화면 **기록** 탭: 이벤트·열쇠 건넴 내려받기, 서랍 내보내기·가져오기.
- 서버·DB·better-auth·마이그레이션·시드 스크립트와 그 의존성을 지운다. 정적 SPA로 빌드한다.
- PWA: 매니페스트, 아이콘, 서비스 워커(모든 빌드 파일 미리 캐시), 글꼴 오프라인.

## 인수 조건

- [x] IndexedDB 서랍·공개 버전·이벤트·열쇠 건넴·주인 잠금 저장소가 메모리와 같은 계약을 통과한다.
- [x] 다시 연 DB에서도 앞서 저장한 값이 그대로 나온다.
- [x] PIN·비밀번호는 해시로만 저장되고, 맞는 값만 통과한다. 5번 틀리면 60초 잠긴다.
- [x] 운영 비밀번호가 없으면 정하는 화면, 있으면 들어가는 화면이 나온다.
- [x] 빈 기기를 처음 열면 시드 서랍과 공개 버전 1이 생기고, 다시 열어도 또 만들지 않는다.
- [x] 내려받은 기록에 별명이 없고, 모든 행에 버전이 있다(I-12·I-16).
- [x] 내보낸 서랍을 가져오면 같은 서랍·문항·책이 된다. 틀린 파일은 아무것도 바꾸지 않는다.
- [x] `server/`, elysia, better-auth, drizzle, PGlite, postgres, nitro가 앱에서 사라진다.
- [x] `bun run build`가 정적 파일과 서비스 워커를 낸다.

## 작업하며 배운 것

- 포트와 계약 테스트가 이미 있어서 저장소를 바꾸는 일은 IndexedDB 구현 하나와 계약 호출 몇 줄이었다.
  예전 API 테스트가 지키던 동작(PIN 잠금, I-11, I-12)은 유스케이스·계약 테스트로 옮겨야 사라지지 않는다.
- 이벤트를 `toFunnelEventDto`로 먼저 옮긴 뒤 파싱하면 모르는 필드가 조용히 떨어져 I-12가 뚫린다.
  받은 값을 그대로 먼저 파싱한다. HTTP 경계가 없어진 뒤에는 저장소가 마지막 경계다.
- idb 트랜잭션에서 `tx.abort()`는 `tx.done`을 처리되지 않은 거절로 남긴다. 쓰기 전이면 그냥 던진다.
- siheom의 `query.text`는 JSX 보간으로 나뉜 글을 찾지 못한다. 문장을 템플릿 문자열 하나로 두거나
  이름 있는 status·접근성 스냅샷으로 확인한다. 필드 오류는 `assertions.description`으로 본다.
- Korean 가변 글꼴 두 벌(woff2 248개, 약 10MB)을 미리 받는다. 키오스크라 받아들였지만, 더 줄이려면
  Serif를 빼는 것이 가장 크다.
- 실제 기기 확인(홈 화면 추가 → 비행기 모드로 열기)은 이 작업에서 하지 않았다. RUNBOOK의 순서로 사람이 본다.
