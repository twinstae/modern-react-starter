# 시드 질문 세트: 가정 문구와 주인 확인 사항

`src/domain/seed-question-set.ts`의 MVP 시드 질문 세트를 설명한다. 이 문서는 문구를
확정하는 문서가 아니라, **책방 주인 선생님이 검토할 목록**과 지금 측정한 점검 결과를
남기는 문서다. 코드는 이 `[가정]` 문구로 먼저 돌아간다.

## 1. 지금의 시드

- 서랍: PRD 부록 B의 7개(B1~B7). 서랍 순서(동점용)는 B6, B1, B4, B2, B7, B3, B5.
- 문항: 서랍마다 2개, 모두 문항형(1~5), 반대 문항 없음. 채점은 `item-mean`.
- 문항 순서: 서랍이 몰리지 않게 섞었다(14문항).
- 기준 응답: 서윤. B6 평균 4.5, B1 평균 3.5로 **1순위 B6, 2순위 B1**을 기대한다.

## 2. 지금 측정한 점검 결과

`analyze`를 표본 4,000개, 고정 시드 79(`seededRng`)로 돌린 결과다. 비율은 0~1이고
표본은 매번 같은 시드로 새로 만든다. 시드 점검은
`src/domain/seed-question-set.test.ts`에서 도메인 테스트로 매번 돈다.

| 서랍 | 1순위 비율      | 1·2순위 비율 |
| ---- | --------------- | ------------ |
| B6   | 0.17875 (17.9%) | 0.3255       |
| B1   | 0.16275 (16.3%) | 0.31275      |
| B4   | 0.1565 (15.7%)  | 0.3015       |
| B2   | 0.14375 (14.4%) | 0.28375      |
| B7   | 0.13675 (13.7%) | 0.2805       |
| B3   | 0.11125 (11.1%) | 0.24875      |
| B5   | 0.11025 (11.0%) | 0.24725      |

- 결정됨: 4,000 / 4,000 (실패 0).
- 서랍 순서까지 간 동점: 906 / 4,000 (22.65%).
- "비슷함" 표시: 2,914 / 4,000 (72.85%).
- 구조: 서랍마다 문항 2개, 빈 서랍 없음, 기준 응답 일치.
- 게이트: **통과**. 실패 0, 경고 0.

## 3. 점검 규칙(지금 코드)

- 막는 실패: 표본에서 결정 실패, 서랍별 1순위 비율이 10~18% 밖, 문항 없는 서랍,
  기준 응답의 실제 순위가 기대와 다름.
- 경고: 서랍별 문항 수 불균형(빈 서랍은 실패), 쌓인 응답의 쏠림. 쌓인 응답은
  R-3에 따라 50~100건이 쌓이면 실제 분포를 기준으로 보는 것을 검토한다.
- 통과는 실패가 하나도 없을 때만이다. 경고는 공개를 막지 않는다.
- 실패·경고는 화면이 문장을 고를 수 있게 코드(`sample-skew`, `empty-drawer`,
  `item-count-imbalance`, `baseline-mismatch` 등)와 서랍 코드로 돌려준다.

## 4. 주인 선생님이 검토할 것

1. **문항 문구 14개.** 지금은 모두 `[가정]`이다. 손님이 서서 읽어도 바로 이해되는지,
   책방의 말투와 맞는지 봐 주세요. 문구만 바꾸는 후속 커밋을 따로 둔다.
2. **서윤 기준 응답.** "B6이 1순위, B1이 2순위"가 의도한 결과인지 확인해 주세요.
   다른 기대가 있으면 기준 답과 기대 순위를 함께 고친다.
3. **서랍당 문항 2개.** R-1(지친다)과 쏠림 사이의 선택이다. 지금 B6는 17.9%로
   상한(18%)에, B5는 11.0%로 하한(10%)에 가깝다. 3개로 늘리면 분포가 고르게
   퍼지지만 문항이 21개가 된다. 늘릴지는 현장에서 정한다.
4. **반대 문항.** 지금은 없다. R-2(모두 4~5로 답하는 동의 편향)를 줄이려면 서랍마다
   반대 문항을 하나씩 두는 안을 검토한다. 넣으면 기준 응답과 점검을 다시 잰다.
5. **서랍 순서.** 동점이 끝까지 갈 때만 쓰지만, 지금 표본의 22.65%가 이 규칙까지
   간다. B6 다음이 B1인 지금 순서가 주인의 의도와 맞는지 봐 주세요.
6. **10~18% 기준.** 이 기준을 바꾸려면 코드의 상수를 슬쩍 풀지 않고, 먼저 스펙과
   이 문서에서 합의한다. 시드가 기준을 넘지 못하면 이유와 결정 요청을 여기에 남긴다.

## 5. 다음에 문구를 바꿀 때

1. `src/domain/seed-question-set.ts`의 문항 문장만 고친다(순서·서랍은 유지).
2. `src/domain/seed-question-set.test.ts`의 시드 점검을 돌린다.
3. 표본 비율이 바뀌면 이 문서의 표와 테스트의 기대값을 함께 고친다.
4. 점검이 실패하면 기준을 느슨하게 하지 말고, 실패 이유와 결정 요청을 이 문서에 더한다.
