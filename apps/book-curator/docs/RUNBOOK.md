# 실행 안내

태블릿 키오스크를 로컬에서 띄우고 확인하는 순서다. 데이터는 `.data/pglite`(git 무시)에
남는다.

## 처음 한 번

```bash
cd apps/book-curator
bun install                 # 루트에서 이미 했으면 생략
bun run seed:published      # 시드 내용이 바뀌었을 때만 새 공개 버전을 만든다
```

시드에는 공개 질문 세트만 들어간다. 서가(책·수량)는 TICKET-00010의 운영 화면이나
별도 시드로 채운다. 아직 공개 버전이 없으면 키오스크는 "질문을 준비하고 있어요"를
보여 준다. 시드 문구나 서랍 데이터가 바뀌면 `seed:published`가 새 버전을 만든다.
공개 버전은 고치지 않는다(I-11).

## 운영자 계정과 주인 PIN

가입 화면은 없다. 환경 변수로 운영자 한 명을 만든다. 같은 이메일이 이미 있으면
아무것도 바꾸지 않으므로 다시 돌려도 안전하다. 비밀번호는 로그에 남기지 않는다.

```bash
cd apps/book-curator
ADMIN_EMAIL=owner@example.com \
ADMIN_PASSWORD='bookshop-79-1' \
ADMIN_NAME='책방 주인' \
bun run seed:operator
```

- 운영자 화면은 `http://localhost:3002/admin`이다. 로그인한 뒤 주인 PIN(숫자 4~6자리)을
  정하거나 바꾼다. PIN은 해시로만 저장된다.

## 서가와 서랍 채우기

공개 질문 세트가 먼저 있어야 서랍 이름·표시를 읽을 수 있다. 없으면 서가 탭이 409
(`NO_PUBLISHED_QUESTION_SET`)로 "질문 세트를 먼저 공개해 주세요"를 보여 준다.

```bash
cd apps/book-curator
bun run seed:published      # 공개 버전이 없을 때만
ADMIN_EMAIL=owner@example.com \
ADMIN_PASSWORD='bookshop-79-1' \
ADMIN_NAME='책방 주인' \
  bun run seed:operator
bun run dev                 # http://localhost:3002/admin
```

1. `/admin`에 로그인하고 **서가** 탭에서 `책 추가`를 누른다. 부록 C의 제목·저자·핵심
   단어·권하는 이유·함께 생각해 볼 질문과 서랍별 관련도(0~5 정수)를 넣는다. 관련도
   칸의 이름은 지금 공개된 서랍 이름이다. 저장하면 목록과 서랍 탭이 함께 새로 읽힌다.
2. **서랍** 탭에서 서랍마다 책을 고르고 수량을 넣는다. 수량을 고치면 입력칸에서
   포커스가 빠지거나 Enter를 누를 때 저장된다. `빼기`는 줄을 지우고, 수량 0은 “없음”으로
   남긴다(R-9).
3. 서랍마다 수량 1 이상인 책이 3종 미만이면 카드에 경고가 보인다(I-7). 경고는 입력을
   막지 않지만, 그 서랍은 아직 열쇠를 건넬 수 없다.
4. **주인 PIN** 탭은 TICKET-00009와 같다. PIN은 해시로만 저장된다.

서랍 표시(`mark`)는 공개 질문 세트가 소유한다. 이 화면에서는 읽기만 하고, 바꾸려면
새 질문 세트 버전을 공개한다(TICKET-00011, I-11). 키오스크 묶음에는 손님에게 필요한
서랍별 책(제목·저자·이유·질문·수량)만 들어가고 관련도는 들어가지 않는다.

- 주인 토큰은 태블릿 메모리에만 두고 10분 뒤 끝난다. 아래 "주인 확인과 서랍 속 책"이
  그 토큰으로 열쇠 건넴·산 책 기록을 남긴다.
- 개발에서는 `BETTER_AUTH_SECRET`이 없어도 요청 origin으로 동작한다. 배포에서는
  `BETTER_AUTH_SECRET`(길고 무작위인 값)과 `BETTER_AUTH_URL`(실제 공개 주소)을 정한다.
  `BETTER_AUTH_URL`을 넣지 않으면 better-auth가 경고를 남긴다.
- 확인:

  ```bash
  curl -i http://localhost:3002/api/admin/me          # 401
  curl -i -H 'content-type: application/json' \
    -d '{"pin":"4821"}' http://localhost:3002/api/owner/unlock
  ```

## 주인 확인과 서랍 속 책 (TICKET-00012)

손님이 결과 화면에서 `주인 확인`을 누르면 주인 모드로 들어간다. 이 화면은 손님의
노란 결과 화면과 달리 빨간 seal 테두리와 "주인 모드" 표시를 쓴다.

1. **PIN.** `주인 PIN`(숫자 4~6자리)을 넣고 `열기`를 누른다. 서버가 PIN을 확인하고
   10분짜리 주인 토큰을 준다. 토큰은 이 탭의 라우트 메모리에만 있고 localStorage·
   쿠키·URL에 쓰지 않는다. `손님 화면으로`를 누르면 토큰을 버리고 결과로 돌아간다.
2. **주인 확인.** 추천 서랍을 가장 크게, 2순위 서랍과 "비슷함" 한 줄, 모든 서랍의 책과
   수량, 3종 미만 경고를 보여 준다. 서랍 표시(번호·열쇠)가 가장 크다.
3. **열쇠 건넴.** `이 서랍 열쇠 건넴`은 추천 서랍으로, 다른 서랍 카드의
   `{서랍 이름} 열쇠 건넴`은 그 서랍으로 기록된다. 추천과 건넨 서랍을 함께 남기므로
   추천과 다르게 건넨 차례도 기록에서 드러난다(R-7). 서버 기록은 추가 전용이다.
4. **서랍 속 책.** 손님 화면은 건넨 서랍의 책만 보여 준다(제목·저자·권하는 이유·함께
   생각해 볼 질문). 다른 서랍 정보는 보이지 않는다(I-9). 수량 0인 책은 "없음"으로
   남고 기록 버튼도 꺼진다(R-9).
5. **산 책 기록.** 화면 아래 작은 주인용 칸에서 책마다 `이 책 기록`을 누르면 산 책이
   추가 전용으로 남고 그 서랍의 수량이 1 줄어든다. 수량은 0 아래로 내려가지 않는다.
   주인 토큰이 끝나면 기록 버튼이 꺼지지만 책 화면은 유지된다.
6. **처음으로.** `처음으로`는 `reset`(`completed`)을 남기고 차례·별명·답·결과를 버린다.
   다음 손님은 새 세션 ID로 시작한다(I-13).

- 주인 모드에서는 손님 유휴 타이머(90초 안내, 120초 종료)를 멈춘다. 주인이 서가를
  살피는 시간을 자르지 않기 위해서다. 대신 10분 주인 토큰 만료가 쓰기 동작의
  안전장치이고, 건넨 뒤에는 산 책 기록만 닫는다.
- PIN을 5번 연속 틀리면 60초 잠긴다. PIN을 아직 정하지 않았으면 409로 안내한다.
- 토큰 없이 `/api/owner/handover`, `/api/owner/purchases`를 부르면 401이다. 만료된
  토큰도 401이라 라우트는 조용히 PIN 화면으로 돌아간다.

## 질문 세트 고치기와 공개 (TICKET-00011)

`/admin`의 **질문 세트** 탭에서 한다. 공개 버전은 고치지 않고, 초안을 고친 뒤 점검을
통과하면 새 버전으로 공개한다(I-11).

1. **초안 준비.** `공개 버전 복제`는 지금 공개 중인 질문 세트를 그대로 복제한다. 공개
   버전이 없으면 409라 먼저 `bun run seed:published`로 시드를 공개한다. 새 이름으로
   `초안 만들기`를 누르면 시드 질문 세트에서 시작한다.
2. **문항 쓰기.** 서랍 카드마다 문항 수가 보인다. 문항을 더하거나 빼고, 문장과 `반대`를
   고친다. 저장은 아직 초안에만 한다. 문항 구조를 바꾸면 기존 기준 응답은 저장할 때
   비워진다(기준 응답은 읽기 전용).
3. **서랍 설정.** 이름, 핵심 단어(쉼표), 표시, 권하는 이유, 서랍별 상태 문장, 서랍
   순서를 고친다. 공통 문장 틀과 인용 문형은 한 카드에 모아 둔다. 오른쪽 미리보기에서
   실제 손님 화면과 같은 코어로 조사·별명·둘째 문장·인용·문항 다섯 칸을 확인한다.
4. **저장.** `초안 저장`이 도메인 파서를 통과한 질문 세트만 저장한다. 빈 문장, 겹친 핵심
   단어, 겹친 서랍 순서, 잘못된 문장 틀은 저장 전에 막힌다.
5. **점검.** 저장하면 점검 보고가 다시 돈다. 표본 4,000건과 `result_view` 이벤트의 답을
   나란히 보여 주고, 서랍별 1순위 비율(10~18%), 문항 수 균형, 기준 응답, 서가 게이트를
   적는다. 실패와 경고, 공개를 막는 이유가 그대로 보인다.
6. **공개.** `새 버전으로 공개`는 점검과 서가 게이트를 통과했을 때만 열린다. 눌러도
   서버가 같은 `analyze`와 게이트를 다시 돌리므로 화면의 보고만 믿지 않는다. 통과하면
   새 버전 번호가 붙고 공개 포인터만 옮겨 간다. 이전 버전 행은 그대로 남는다.

- 공개 점검이 실패하면 422와 이유 코드(`sample-skew`, `baseline-mismatch`,
  `shelf-gate` 등)가 돌아온다. 서가 게이트는 모든 서랍에 책이 3종 이상일 때 통과한다
  (I-7). 서가 탭에서 먼저 책과 수량을 채운다.
- 쌓인 응답이 아직 없으면 보고에 그 자리가 없다. 응답은 별명 없이 `result_view`의 답만
  쓴다(I-12).
- 문항 수는 데이터다. 서랍마다 문항 수가 달라도 점검·게이트를 통과하면 공개되고,
  키오스크는 새 묶음의 문항 수 그대로 돈다(I-5).

## 개발

```bash
cd apps/book-curator
bun run dev                 # http://localhost:3002
bun run storybook           # http://localhost:6008
```

- 태블릿 세로 834×1112, 가로 1112×834 뷰포트가 Storybook 기본값이다.
- 키오스크 흐름: 별명 → 문항 → 결과 → (주인 확인) → 서랍 속 책 → 처음으로.
- 손님 차례에는 유휴 90초에 "계속하시겠어요?"가 한 번 뜨고, 120초에 처음 화면으로
  돌아간다. 값은 `src/domain/idle.ts`의 `IDLE_LIMITS`다. 주인 모드에서는 이 타이머를
  멈추고 10분 주인 토큰 만료를 쓴다.
- 태블릿 이름은 `VITE_KIOSK_NAME`으로 정한다. 예: `VITE_KIOSK_NAME="창가 자리" bun run dev`.
  없으면 "계산대 옆"이다. 이벤트의 `kioskName`에만 쓰고 사람과 연결하지 않는다.
- 이벤트는 `POST /api/events`로 `.data/pglite`의 `funnel_events`에 추가 전용으로 쌓인다.
  전송이 실패해도 화면을 막지 않고, 다음 전송 때 남은 것부터 다시 보낸다.

## 확인

```bash
cd apps/book-curator
bun run check               # design boundary + lint + format + typecheck + test
bun run build               # 프리렌더까지 확인. API·DB는 첫 요청 때 열린다
bun run check:layout        # Storybook이 6008에 떠 있을 때 화면 겹침·넘침 검사
bun run test run src/domain/turn.test.ts   # 좁은 테스트
```

- API만: `curl http://localhost:3002/api/health`,
  `curl http://localhost:3002/api/kiosk/current`.
- `bun run check`가 PGlite 테스트 때문에 몇 초 걸린다. 정상이다.
- `check:layout`은 `bun run storybook`을 먼저 띄운 뒤 다른 터미널에서 돌린다.
  세로 834×1112, 가로 1112×834에서 결과·질문·별명·주인 확인·서랍 속 책 화면의
  직접 자식이 겹치거나 화면을 넘지 않는지 본다.
- 루트 `bun run ci`는 `apps/simple-event`와 `solo-quest`의 기존 오류로 실패한다.
  book-curator 게이트로 쓰지 않는다.

## 자주 막히는 곳

- 첫 화면이 "준비 중"이면 `bun run seed:published`를 안 돌린 것이다.
- Storybook에서 TanStack Start/nitro 플러그인 오류가 나면 `.storybook/main.ts`의
  `viteFinal`이 서버 플러그인을 걸러 내는지 본다.
- 컴포넌트 테스트가 "Failed to import test file"로 죽으면 브라우저 프로젝트의
  `fileParallelism: false`가 유지되는지 본다.
- Panda가 `design_system_token_conflict` info를 내는 것은 앱 테마가 `canvas`·`fg`·
  `border`를 의도적으로 덮기 때문이다. 로컬 값이 이긴다.
