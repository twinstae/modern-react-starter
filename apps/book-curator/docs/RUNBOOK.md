# 실행 안내

태블릿 키오스크를 띄우고 확인하는 순서다. 서버는 없다. 앱은 정적 파일만으로 된 PWA이고,
서랍·공개 버전·기록·PIN은 모두 **그 태블릿 브라우저의 IndexedDB**에만 있다(ADR 0006).

## 태블릿에 설치하기

1. `bun run build`로 만든 `dist/`를 정적 호스팅(Vercel 등)에 올린다. 서비스 워커는 HTTPS(또는
   `localhost`)에서만 켜진다.
2. 태블릿을 인터넷에 연결하고 그 주소를 연다.
   - iPad: Safari에서 열고 공유 → **홈 화면에 추가**.
   - 안드로이드: Chrome에서 열고 메뉴 → **앱 설치**(또는 홈 화면에 추가).
3. 홈 화면 아이콘으로 한 번 연다. 이때 서비스 워커가 앱 파일과 글꼴(약 11MB)을 모두 받아 둔다.
   그 뒤로는 인터넷 없이 열린다. 비행기 모드로 아이콘을 눌러 열리는지 확인한다.
4. 빈 기기를 처음 열면 시드 서랍 7개가 들어가고 버전 1이 공개돼 손님 화면이 바로 돈다.

- 새 버전을 올리면 태블릿이 온라인일 때 새 파일을 받아 두고, **앱을 다시 열 때** 적용된다.
- 브라우저가 저장 공간이 모자랄 때 데이터를 지우지 않도록 영구 저장을 요청한다. 그래도
  **사이트 데이터를 지우거나 홈 화면 앱을 지우면 서랍과 기록이 사라진다.** 기록 탭에서 자주
  내려받는다.
- iPad는 홈 화면에 추가한 앱과 Safari 탭의 저장소가 따로다. 늘 홈 화면 아이콘으로 연다.

## 운영 비밀번호와 주인 PIN

- 운영자 화면은 `/admin`이다. 처음 열면 **운영 비밀번호 정하기**가 나온다(8자 이상, 두 번).
  이 기기에 해시로만 저장되고, 잊으면 되찾을 수 없다. 다음부터는 그 비밀번호로 들어간다.
  로그인은 그 탭에서만 유지되고, 앱을 다시 열면 다시 넣는다.
- 탭은 **서랍**, **주인 PIN**, **글꼴**, **기록** 넷이다.
- **글꼴**에서 키오스크 화면의 글꼴을 고른다. 기기마다 저장된다.
- **주인 PIN**에서 `새 PIN 만들기`를 누르면 숫자 6자리가 한 번 보인다. 해시로만 저장되므로
  잊으면 새로 만든다. 새로 만들면 예전 PIN은 더 쓸 수 없다. 운영 비밀번호와 다르다.

## 서랍 채우기와 공개

서랍은 이름, 문항, 책만 가진다. 책은 제목·저자·출판사뿐이고 한 서랍에만 든다.

1. **서랍 만들기.** **서랍** 탭 아래 `새 서랍 이름`을 넣고 `서랍 만들기`를 누르면 그
   서랍 페이지로 간다. 목록 순서는 만든 순서이고, 동점이 끝까지 가면 앞 서랍이 이긴다.
2. **문항.** 서랍 페이지의 `문항` 칸에 한 줄에 하나씩 쓴다. 이 서랍이 맞는 손님이라면
   "그렇다"고 답할 문장이다. 서랍마다 2~3개를 권한다. 손님에게는 서랍들의 문항이
   서랍마다 돌아가며 섞여 나온다.
3. **책 올리기.** `양식 내려받기`로 CSV 양식을 받아 채운다. 첫 줄은 `제목,저자,출판사`,
   그 아래 한 줄에 한 권이다. 출판사는 비워도 된다. 엑셀은 "CSV UTF-8(쉼표로 분리)"로,
   구글 시트는 파일 → 다운로드 → 쉼표로 구분된 값(.csv)으로 저장한다. 엑셀의 그냥 "CSV"
   (CP949)도 읽는다. 파일을 고르면 먼저 읽어 보여 주고, `N권 올리기`를 눌러야 서랍에
   더해진다. 한 줄이라도 틀리면 몇 번째 줄인지 알려 주고 아무것도 올리지 않는다.
4. **책 고치기.** 표에서 `고치기`·`빼기`로 한 권씩 다루고, `책 한 권 더하기`로 손으로 한
   권을 더한다.
5. **공개.** **서랍** 탭 아래 `손님 화면에 공개`에서 `지금 서랍으로 공개`를 누르면 지금
   서랍·문항·책이 새 버전이 된다. 서랍을 고쳐도 다시 공개하기 전까지 태블릿은 앞 버전을
   쓴다. 서랍이 2개 미만이거나 문항 없는 서랍이 있으면 공개하지 않는다. 결과가 한 서랍에
   쏠리거나(서랍 수에 맞춘 1/N의 0.7~1.26배 밖), 문항 수가 서랍마다 다르거나, 책이
   3권보다 적으면 경고만 한다.

## 주인 확인과 열쇠 건넴

1. 손님이 결과 화면에서 `주인 확인`을 누르면 PIN 화면이 나온다. 맞으면 주인 확인이 10분 열린다.
   열린 상태는 손님 차례 메모리에만 있다(I-15).
2. 주인 확인은 추천 서랍, 2순위 서랍, 모든 서랍의 책 제목·저자를 보여 준다.
   `이 서랍 열쇠 건넴` 또는 `{서랍 이름} 열쇠 건넴`을 누르면 추천과 건넨 서랍이 함께
   기록된다(R-7).
3. 태블릿은 "{서랍 이름} 서랍을 열어 보세요"를 보이고, `처음으로`를 누르거나 120초가
   지나면 다음 손님을 위해 처음 화면으로 돌아간다(I-13).

- PIN을 5번 연속 틀리면 60초 잠긴다. PIN을 아직 만들지 않았으면 운영 화면에서 먼저 정하라고 안내한다.
- 10분이 지나면 확인 화면은 PIN 화면으로 돌아간다.

## 기록과 서랍 옮기기

**기록** 탭에서 한다. 태블릿마다 데이터가 따로이고 동기화는 없다.

- `기록 내려받기`: 퍼널 이벤트와 열쇠 건넴을 `책방79-1-기록-날짜.json` 하나로 받는다. 별명은
  들어 있지 않다(I-12). 여러 태블릿이면 대마다 받아 세션 ID로 합친다.
- `서랍 내보내기`: 서랍·문항·책을 `책방79-1-서랍-날짜.json`으로 받는다. 백업이나 다른 태블릿용이다.
- 서랍 파일 가져오기: 파일을 끌어 놓거나 고르면 서랍·책 수를 보여 주고, `이 서랍으로 바꾸기` →
  확인 창의 `바꾸기`로 이 기기의 서랍을 **모두** 바꾼다. 틀린 파일은 아무것도 바꾸지 않는다.
  손님 화면은 **서랍** 탭에서 다시 공개할 때까지 앞 버전 그대로다.

## 개발

```bash
cd apps/book-curator
bun run dev                 # http://localhost:3002
bun run storybook           # http://localhost:6008
```

- 태블릿 세로 834×1112, 가로 1112×834 뷰포트가 Storybook 기본값이다.
- 키오스크 흐름: 별명 → 문항 → 결과 → (주인 확인) → 서랍 속 책 → 처음으로.
- 손님 차례에는 유휴 90초에 "계속하시겠어요?"가 한 번 뜨고, 120초에 처음 화면으로
  돌아간다. 값은 `src/domain/idle.ts`의 `IDLE_LIMITS`다. 주인 모드에서는 이 타이머를
  멈추고 10분 주인 토큰 만료를 쓴다.
- 태블릿 이름은 빌드할 때 `VITE_KIOSK_NAME`으로 정한다. 예: `VITE_KIOSK_NAME="창가 자리" bun run build`.
  없으면 "계산대 옆"이다. 이벤트의 `kioskName`에만 쓰고 사람과 연결하지 않는다.
- 이벤트는 기기의 IndexedDB에 추가 전용으로 쌓인다. 저장이 실패해도 화면을 막지 않고,
  다음 저장 때 남은 것부터 다시 넣는다.
- 개발 서버(`bun run dev`)에서는 서비스 워커를 켜지 않는다. 오프라인 동작은
  `bun run build && bun run preview`로 본다.
- 개발 중 데이터는 브라우저 개발자 도구 → Application → IndexedDB의 `book-curator`에 있다.

## 확인

```bash
cd apps/book-curator
bun run check               # design boundary + lint + format + typecheck + test
bun run build               # dist/에 정적 파일과 sw.js를 낸다
bun run check:layout        # Storybook이 6008에 떠 있을 때 화면 겹침·넘침 검사
bun run test run src/domain/turn.test.ts   # 좁은 테스트
```

- 저장소 계약 테스트는 node에서 `fake-indexeddb` 위로 돈다.
- `check:layout`은 `bun run storybook`을 먼저 띄운 뒤 다른 터미널에서 돌린다.
  세로 834×1112, 가로 1112×834에서 결과·질문·별명·주인 확인·서랍 속 책 화면의
  직접 자식이 겹치거나 화면을 넘지 않는지 본다.
- 루트 `bun run ci`는 `apps/simple-event`와 `solo-quest`의 기존 오류로 실패한다.
  book-curator 게이트로 쓰지 않는다.

## 데이터 초기화

브라우저(또는 홈 화면 앱)의 사이트 데이터를 지운다. 개발 중에는 개발자 도구 → Application →
Storage → Clear site data. 다시 열면 빈 기기처럼 시드 서랍이 공개된다.
**실제 태블릿에서는 먼저 기록 탭에서 기록과 서랍을 내려받는다.**

## 자주 막히는 곳

- 첫 화면이 "준비 중"이면 공개 버전이 없는 것이다. 서랍을 지우고 공개한 적이 없으면 생긴다.
  운영 화면에서 서랍을 채우고 공개한다.
- 오프라인에서 안 열리면 홈 화면 아이콘으로 온라인일 때 한 번 열었는지, HTTPS 주소인지 본다.
- Storybook에서 TanStack Router 플러그인 오류가 나면 `.storybook/main.ts`의
  `viteFinal`이 그 플러그인을 걸러 내는지 본다.
- 컴포넌트 테스트가 "Failed to import test file"로 죽으면 브라우저 프로젝트의
  `fileParallelism: false`가 유지되는지 본다.
- Panda가 `design_system_token_conflict` info를 내는 것은 앱 테마가 `canvas`·`fg`·
  `border`를 의도적으로 덮기 때문이다. 로컬 값이 이긴다.
