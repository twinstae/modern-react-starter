# 서버 없이 태블릿 브라우저의 IndexedDB로만 돌고, PWA로 설치한다

책방 태블릿은 인터넷이 없어도 하루 내내 돌아야 한다. 서버(elysia + supabase postgres + better-auth)를
걷어 내고, 모든 저장소를 태블릿 브라우저의 IndexedDB에 둔다. 앱은 정적 파일만으로 된 PWA이고, 한 번
열어 "홈 화면에 추가"하면 서비스 워커가 모든 자산을 캐시해 그 뒤로는 오프라인으로 돈다.

이 ADR은 0003의 "공개 점검은 서버에서 같은 코어를 돌린다"와 0005의 better-auth·주인 토큰을 대신한다.

## Decision

- 포트(`DrawerStore`, `PublishedVersionStore`, `EventStore`, `HandoverStore`, `OwnerAccessStore`)는
  그대로 두고, 구현을 메모리 + IndexedDB 둘로 한다. 두 구현은 같은 `*.contract.ts`를 통과한다.
  node 테스트는 `fake-indexeddb`의 새 `IDBFactory`를 주입한다.
- 라우트·화면은 HTTP 대신 브라우저 안의 유스케이스를 바로 부른다. `admin-api.ts`·`owner-api.ts`의
  함수 이름과 돌려주는 모양은 그대로 둔다.
- 운영 화면은 **운영 비밀번호**로 연다. 처음 열 때 정하고, 해시만 기기에 둔다. 주인 PIN(6자리)과
  따로 두어 PIN을 아는 사람이 서랍을 고칠 수 없다. 로그인 상태는 탭 메모리에만 있다.
- PIN·비밀번호 해시는 Web Crypto PBKDF2-SHA256이다. 서버가 없으니 주인 토큰도 없다. 주인 잠금
  해제는 손님 차례 메모리의 10분짜리 상태다(I-15는 화면 분리로 지킨다).
- 퍼널 이벤트·열쇠 건넴은 기기에 추가 전용으로 쌓고, 운영 화면에서 파일로 내려받는다.
  서랍은 JSON으로 내보내고 가져와 다른 태블릿으로 옮기거나 백업한다.
- 빈 기기를 처음 열면 시드 서랍을 넣고 첫 버전을 공개한다.

## Consequences

- 태블릿마다 데이터가 따로다. 동기화는 없고, 옮기는 길은 내보내기·가져오기 파일뿐이다.
- 브라우저 데이터를 지우거나 앱을 지우면 기록이 사라진다. `navigator.storage.persist()`를 요청하고,
  운영자가 기록을 자주 내려받게 안내한다.
- 비밀번호와 PIN은 기기 안의 해시라, 기기를 손에 쥔 사람의 오프라인 대입은 막지 못한다. 막는 것은
  손님이 화면에서 운영·주인 화면을 여는 일이다.
- 서버·DB·인증·마이그레이션 코드와 의존성이 사라져 앱이 작아진다. 예전 코드는 git 기록에 남는다.
