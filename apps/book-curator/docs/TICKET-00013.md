# TICKET-00013: [v2·탐색] 학습 데이터, 학습 모델 채점 방식, v1과 비교

- 스펙: [TECH_SPEC](TECH_SPEC.md) §2.2, §4.3, R-7, R-8, PRD 부록 A-4
- Blocked by: TICKET-00008, TICKET-00011, TICKET-00012. 실제 응답 50~100건이 쌓인 뒤 시작한다
- Status: blocked (v2, 실제 현장 데이터 대기)

## 지금 상태 (2026-10-25)

TICKET-00008/00011/00012는 끝났지만, 이 티켓의 전제인 **실제 손님 응답 50~100건**이
없다. 로컬 시드·합성 답으로 학습·비교를 하면 “v1보다 나은가”를 판단할 수 없고,
티켓이 경고한 R-7(주인이 추천을 그대로 건넴)·R-8(과적합)을 그대로 재현한다.
그래서 학습 모델·비교·채택은 시작하지 않는다. 데이터가 쌓인 뒤 바로 시작할 수 있도록
[`T13-READINESS.md`](T13-READINESS.md)에 선행 조건과 순서를 남겼다.

내보내기부터 먼저 만들지도 않았다. 내보낼 실제 행이 없고, 데이터가 생기면
`result_view`·`handover`·`purchase`의 세션 ID 조인부터 확인해야 하기 때문이다.

## 만들 것

- **학습 데이터 내보내기:** 운영자가 익명 (버전, 답 목록, 추천 서랍, 건넨 서랍, 산 책의 서랍) 목록을 내려받는다. `result_view`와 열쇠 건넴·산 책을 세션 ID로 잇는다.
- **`learned` 채점 방식:** 학습한 모델(우선 의사결정 나무)을 JSON으로 공개 버전에 담고, 같은 `DrawerScores`를 낸다. 서랍 점수는 나무 잎의 서랍별 비율 등으로 만든다.
- **학습:** 앱 밖 스크립트로 시작한다(`bun run train`). 내보낸 데이터 → 나무 JSON. 앱 안 학습 버튼은 만들지 않는다.
- **비교:** 같은 데이터로 v1과 학습 모델을 견주는 보고 — 건넨 서랍과의 일치율, "추천과 다르게 건넴"에서의 일치율, 공개 점검의 분포.
- **채택:** 관리자가 학습 모델을 초안에 넣고, 점검을 통과하면 새 버전으로 공개한다. 여러 차례 다시 학습할 수 있다.

## 알아야 할 것

- 이 티켓은 **탐색이다.** 데이터 양, 정답의 질(R-7), 과적합(R-8)을 보고 계속할지 정한다. 결과가 v1보다 낫지 않으면 채택하지 않는 것도 성공이다.
- 나무는 사람이 읽을 수 있는 규칙이라 관리자 검토가 쉽다. 규칙을 문장으로 보여 주는 화면은 [탐색].
- 학습 모델도 공개 버전 안의 불변 데이터다. 같은 버전·같은 답이면 같은 결과(I-2), 순위 이후는 v1과 같다(I-6).
- 훈련/평가 데이터를 나눠 같은 데이터로 학습하고 평가하지 않는다.
