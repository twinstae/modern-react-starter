# TICKET-00010: 큐레이터 — 책 등록과 서랍 채우기

- 스펙: [TECH_SPEC](TECH_SPEC.md) §5.3 운영: 서가·서랍, I-7, R-9, PRD UC-07·08, 부록 C
- Blocked by: TICKET-00005, TICKET-00009
- Status: done

## 만들 것

- API(운영자): 책 목록·추가·수정, 서랍마다 책 넣기·빼기·수량 고치기, 서랍 표시 고치기, 게이트 상태 조회.
- 화면: 책 목록 표 + 편집 다이얼로그(부록 C 양식, 관련도 0~5 일곱 칸), 서랍 일곱 칸(서랍마다 책과 수량, 3종 미만 경고).

## 알아야 할 것

- 30~50권을 빠르게 넣는 것이 목적이다. 데스크톱 또는 태블릿 가로, 한 화면에서 목록과 편집.
- 한 책이 여러 서랍에 들어 있을 수 있다(같은 책 여러 권).
- 서랍 화면을 실제 서랍장처럼 격자로 보일지는 [탐색]. 처음엔 서랍별 목록으로 충분하다.
- 필요한 입력 원시 컴포넌트(숫자 입력 등)는 `@repo/ui`에 더한다.

## 인수 조건

- [x] 책을 추가·수정하고 다시 불러오면 같다. 관련도는 0~5 정수만 받는다(api).
- [x] 서랍에 책을 넣고 수량을 고치면 공개 버전 묶음과 주인 확인에 그 수량이 보인다(api).
- [x] 서랍 속 책이 3종 미만이 되면 게이트 조회가 그 서랍을 돌려준다(api, I-7).
- [x] 책 편집 폼이 부록 C 항목을 `onSubmit`에 넘기고, 잘못된 값의 이유를 보여 준다(컴포넌트).
- [x] 서랍 화면에서 3종 미만인 서랍이 경고로 보인다(컴포넌트).
- [x] 스토리: 책 0권, 1권, 50권, 게이트 실패.

## 작업하며 배운 것

- 키오스크 묶음은 질문 세트만 담고 있었다. T12가 건넨 서랍의 책을 보여 주려면 묶음에
  공개 서가가 필요해, 손님에게 필요한 필드만 고르는 `PublicShelfSchema`를 더했다.
  관련도·서랍 코드·점수는 스키마에 자리가 없어 새지 않는다.
- 서랍 표시는 질문 세트가 소유하므로 T10에서 고치지 않았다. 운영 화면은 표시를 읽기만
  하고, 바꾸는 일은 T11의 새 버전 공개로 미뤘다. 이 결정은 OPEN-QUESTIONS에도 남겼다.
- 운영 화면의 단일 query(`adminQueries.shelf()`)가 책·수량·서랍 이름·게이트를 함께
  들고 있어, 책을 저장한 뒤 한 번만 무효화하면 서가와 서랍 탭이 같은 값을 본다.
- PGlite `beforeAll`이 기본 10초를 넘겨 `bun run check`가 간헐 실패했다. 테스트를 더
  늘리면서 병렬 부팅이 겹친 탓이라 `hookTimeout`을 30초로 두었다.
