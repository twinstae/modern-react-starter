# TICKET-00008: 익명 퍼널 이벤트와 정답 표시

- 스펙: [TECH_SPEC](TECH_SPEC.md) I-12, I-14, I-16, R-7, R-10, PRD UC-10
- Blocked by: TICKET-00006 (결과 이후 이벤트는 TICKET-00007, 건넴·구매는 TICKET-00012 뒤에 잇는다)
- Status: done

## 만들 것

- 도메인: PRD UC-10 표의 이벤트 9종 스키마(허용 목록, 엄격). 모든 이벤트에 세션 ID, 태블릿 이름, 질문 세트 버전. **별명 자리는 없다.**
- 도메인: 퍼널 상태기계 `funnel(state, uiAction)` → 보낼 이벤트. 화면은 UI 동작만 알리고, 어떤 이벤트를 남길지는 코어가 정한다.
- 셸: 차례마다 새 세션 ID, 이벤트 큐와 재전송(와이파이 끊김), 처음으로 돌아갈 때 남은 이벤트 보내기.
- API: `POST /api/events` — 스키마를 통과한 필드만 저장. 요청 헤더(IP, User-Agent)를 읽지 않는다.
- 저장소: 추가 전용 이벤트 테이블. 메모리·PGlite 계약 테스트.
- 학습 데이터의 바탕: `result_view`에 답 목록·서랍 점수·순위를 남겨, TICKET-00012의 열쇠 건넴과 세션 ID로 이을 수 있게 한다.

## 알아야 할 것

- 세션 ID는 쿠키·localStorage에 두지 않는다. 차례가 끝나면 버린다.
- 태블릿 이름은 운영자가 태블릿마다 정하는 짧은 글이다. 사람과 무관하다.
- 이벤트는 분석용이다. 보내기에 실패해도 손님 흐름을 막지 않는다.
- 호스팅 접근 로그의 IP 보존은 앱 밖의 운영 확인 항목으로 README에 적는다.

## 작업하며 배운 것

- 질문 스키마에 문항 id가 없어 이벤트의 `questionId`는 질문 세트 버전 + 순서(`q1`, `q2`…)로
  만든다. 문항을 영구 id로 둘지는 `OPEN-QUESTIONS.md`에 남겼다.
- `result_view`의 점수는 `DrawerScores`에서 `drawer`·`score`·`fives`만 명시적으로 골라 담고
  `contributions`는 이벤트에 넣지 않았다. 학습 데이터에 기여가 필요해지면 별도 이벤트나
  세션 ID 조인으로 더한다.
- 라우트는 준비된 묶음이 올 때 세션을 열고 버전을 고정한다. reset 뒤에는 refetch가 끝난
  다음에 상태를 비워, 새 `kiosk_ready`와 그 차례의 `test_start`·`result_view` 버전이
  어긋나지 않게 했다.
- 이벤트 큐는 flush 시작 시 대기 배열을 복사한다. 보내는 동안 새 이벤트가 들어와도 같은
  batch에 섞이지 않고 다음 flush로 간다.
- PGlite는 `.data/pglite`에 하나만 열어야 해서 `openDatabase` 약속 하나를 공개 버전 저장소와
  이벤트 저장소가 함께 쓴다.
