# TICKET-00011: 관리자 — 질문 세트(문항) 편집, 상태 문장, 공개 전 점검, 공개

- 스펙: [TECH_SPEC](TECH_SPEC.md) §2.2, §3.6, §4.3, §5.3 운영: 질문 세트, I-1, I-7, I-11, PRD UC-09·부록 A-3
- Blocked by: TICKET-00003, TICKET-00004, TICKET-00009
- Status: todo

## 만들 것

- API(운영자): 초안 목록·만들기·공개 버전에서 복제·저장, 점검 보고 조회(쌓인 응답 포함), 공개(점검 통과 + 서가 게이트 통과일 때만 새 버전), 버전 목록.
- 화면:
  - 서랍별 문항 목록: 서랍 일곱 칸, 칸마다 문항(문장, 반대 여부). 문항 수가 한눈에 보인다.
  - 문항 미리보기: 손님 태블릿 화면 모양 그대로.
  - 서랍 이름·핵심 단어·상태 문장(조사·별명 미리보기), 인용 문형, 서랍 순서(동점용), 기준 응답.
  - 점검 보고: 분포 막대(표본과 실제 나란히), 문제 목록, 공개 버튼은 통과 때만.

## 알아야 할 것

- 관리자의 일은 **문장을 쓰는 것**이다. 점수표를 맞추는 일이 아니다(PRD 부록 A-2). 화면도 그 일을 가운데 둔다.
- 공개 API는 서버에서 같은 `analyze`를 다시 돈다. 화면의 점검만 믿지 않는다.
- 공개 버전은 고치지 않는다. 고치려면 복제해 초안을 만든다(I-11).
- 선택형 질문 편집은 이번 티켓에서 만들지 않는다(C-1). 스키마는 받지만 편집 화면은 문항형만.
- 점검 보고는 관리자가 "어느 서랍의 문항을 고쳐야 하는지" 알 수 있게 보이는 것이 목적이다. 분포 막대 하나와 문제 목록이 먼저, 세부 표는 접어 둔다.

## 인수 조건

- [ ] 공개 버전을 복제한 초안을 고쳐 저장하고 다시 불러오면 같다(api).
- [ ] 점검을 통과하지 못한 초안, 게이트를 통과하지 못한 서가에서는 공개가 거부되고 이유가 돌아온다(api).
- [ ] 공개하면 새 버전 번호가 생기고 공개 중이 바뀌며, 이전 버전은 그대로다(api, I-11).
- [ ] 서랍마다 문항 수를 바꾼 초안을 공개하면 묶음으로 나오고 키오스크가 그대로 돈다(api + 코어, I-5).
- [ ] 상태 문장 편집에서 서랍 이름에 맞는 조사와 예시 별명이 미리보기에 보인다(컴포넌트).
- [ ] 점검 보고 화면이 쏠림·문항 수 불균형·기준 응답 실패를 보이고, 그때 공개 버튼이 막혀 있다(컴포넌트).
