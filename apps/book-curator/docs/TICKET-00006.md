# TICKET-00006: 키오스크 흐름 — 공개 버전 묶음 API, 별명 화면, 질문 화면, 처음으로

- 스펙: [TECH_SPEC](TECH_SPEC.md) §3.3, §3.4, §5.1~5.3, I-5, I-11, I-12, I-13, R-4, R-10, R-12
- Blocked by: TICKET-00003, TICKET-00005
- Status: todo

## 만들 것

- 질문 세트 공개 버전 저장소(불변 버전 + 공개 중 포인터), 시드로 첫 공개 버전을 만드는 스크립트.
- `GET /api/kiosk/current` → 공개 버전 묶음. 응답 스키마를 건다.
- 화면(표시용 컴포넌트 + 스토리 + 테스트): `NicknameStart`(별명 칸, 시작), `QuestionScreen`(문항, 다섯 칸 척도, 되돌아가기, 진행).
- 라우트: 키오스크 루트 하나가 `Turn` 값을 메모리에 들고, 코어로 진행한다. 유휴 시간 초과·처음으로는 `endTurn`으로 차례를 버린다.
- 앱 테마: 책방79-1의 색·글꼴(문장용 명조, UI용 고딕), 태블릿 기준 글자 크기와 여백 단위.

## 알아야 할 것

- 묶음은 차례가 시작될 때의 것을 쓴다(I-11). 처음 화면으로 돌아올 때 새 묶음이 있으면 바꿔 단다.
- 별명은 서버로 가는 어떤 요청에도 담기지 않는다(I-12). 브라우저 저장소(localStorage 등)도 쓰지 않는다(R-4).
- 차례가 끝나면 브라우저 "뒤로 가기"로 앞 손님 화면이 돌아오지 않게, 차례 안의 단계는 URL이 아니라 메모리 상태로 둔다.
- 유휴 시간 초과는 시각·타이머를 주입해 코어에서 확인한다. 끝나기 전 "계속하시겠어요?" 한 번.
- 척도는 접근성 이름이 있는 라디오 그룹(그룹 이름 = 문항)으로 만들고, 누르면 곧바로 다음 문항이다. 필요한 원시 컴포넌트(RadioGroup 등)는 `@repo/ui`에 더한다.
- 질문 화면은 태블릿 세로·가로에서 스크롤이 없어야 한다. 테스트로 단언하지 않고, 가장 긴 문항 스토리를 두 뷰포트로 본다(R-12).
- 화면 깨우기(Wake Lock)는 qr-quest `use-wake-lock.ts`를 참고한다.

## 인수 조건

- [x] API: 공개 버전이 없으면 "준비 중" 응답, 있으면 묶음을 돌려준다(api).
- [x] API: 새 버전을 공개해도 이전 버전 행은 바뀌지 않는다(저장소 계약, I-11).
- [x] 별명을 넣고 시작하면 `onStart`에 별명이 넘어가고, 빈 별명·너무 긴 별명은 이유를 보여 준다(컴포넌트).
- [x] 척도에서 하나를 누르면 그 값으로 `onAnswer`, 되돌아가기는 `onBack`(컴포넌트).
- [x] 유휴 시간 초과·처음으로 뒤 차례 값에 별명과 답이 없고, 다음 차례는 새 세션 ID다(코어, I-13).
- [x] 문항 수가 다른 질문 세트 fixture로도 같은 화면이 끝까지 진행된다(코어 + 컴포넌트, I-5).
- [x] 스토리: 별명 화면(빈 칸, 오류), 질문 화면(첫 문항, 가장 긴 문항, 마지막 문항), 태블릿 세로·가로.

## 작업하며 배운 것

- 공개 묶음은 `baselines`뿐 아니라 주인용 `mark`도 빼야 손님 경계가 깨끗했다. 서버 응답 스키마와 도메인 파서를 같은 파일에 두니 두 경계가 같은 모양을 쓴다.
- PGlite의 `max(version)`은 드라이버에 따라 문자열로 올 수 있어 `Number()`로 한 번 감쌌다. 계약 테스트를 메모리와 PGlite가 함께 부르니 이 차이가 한 곳에서 드러났다.
- Storybook `StoryObj.args`는 meta args가 있어도 `Partial`로 추론된다. 스토리와 테스트가 같은 픽스처를 쓰려면 `satisfies ComponentProps`로 만든 args 상수를 export하는 편이 안전했다.
- 접근성 오류 메시지는 `role="alert"`만으로는 siheom `errormessage` 단언에 잡히지 않는다. `aria-invalid`와 `aria-errormessage`를 함께 붙여야 사용자와 테스트가 같은 이름을 본다.
