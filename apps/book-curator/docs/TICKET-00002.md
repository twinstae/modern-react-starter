# TICKET-00002: 큐레이션 코어 — 질문 세트, 손님 차례, 채점, 순위

- 스펙: [TECH_SPEC](TECH_SPEC.md) §2.2, §2.5, §4.2
- Blocked by: TICKET-00001
- Status: todo

## 만들 것

DB도 화면도 없는 순수 코어. 질문 세트를 받아 손님이 답하고 되돌아가며, 마지막 답 뒤 1·2순위 서랍이 정해진다.

- `QuestionSet` 스키마(valibot)와 타입: 서랍 정의(코드, 이름, 순서), 질문(문항형: 서랍·반대 여부 / 선택형: 선택지·서랍 가중치), 채점 방식.
- `Turn`: `startTurn / answer / back / endTurn`. 진행 상태는 **답 목록 하나**로 표현한다. 되돌아가면 그 뒤를 잘라 낸다. 별명도 이 값 안에 있다.
- 채점: 공통 `DrawerScores`(서랍별 점수와 기여한 답)를 내는 `item-mean`. `choice-weight`는 같은 모양으로 작게 하나 더(채점 방식이 바뀌어도 뒤가 같음을 확인하기 위해).
- `rank(scores, order)`: 1·2순위, 동점 규칙, "비슷함" 표시.
- 생성기 `question-set.arbitrary.ts`: 서랍 수·문항 수·형식이 무작위인 질문 세트, 그 안의 답·상호작용열.

## 알아야 할 것

- 코어는 프레임워크와 시각·난수를 import하지 않는다.
- 문항 수나 질문 수를 어디에도 가정하지 않는다(I-5).
- 동점 규칙은 PRD 부록 A-3의 [가정](5의 수 → 서랍 순서)으로 시작하고 예시로 고정한다. "비슷함"의 기준값은 작게 정하고 나중에 바꿀 수 있게 둔다.
- `learned` 채점 방식은 이 티켓에서 만들지 않는다(TICKET-00013). 다만 `DrawerScores`가 그것도 받을 수 있는 모양인지 확인한다.

## 작업하며 배운 것

- `DrawerScores`를 채점기가 직접 만들지 않고 `DrawerScoresSchema`로 파싱해 돌려주면, 두 채점 방식이 같은 모양을 낸다는 I-6을 타입만이 아니라 런타임에서도 확인하게 된다.
- 문항이 없는 서랍의 규칙은 "증거 없음 = 점수 0"으로 정했다. `item-mean`은 관측 점수가 1 이상이라 안전하고, `choice-weight`도 가중치가 0보다 크면 안전하다. 서랍을 빼지 않으므로 I-1의 두 서랍이 유지된다.
- 동점 규칙의 "5의 수"는 반대 문항을 뒤집은 **유효값** 기준이다. 그래서 반대 문항에 1을 답한 것도 5 하나로 센다. 선택형에서는 가중치 5를 센다.
- 답 오류는 `InvalidAnswerError` 하나를 던지는 쪽으로 통일했다. `answer`는 `unknown`을 받아 질문 형식과 선택지에 맞는지 확인하므로, 화면의 원시 입력이 도메인 값으로 바뀌는 경계가 한곳에 있다.
- `rank`는 `DrawerScores`의 점수와 5의 수, 인자로 받은 서랍 순서만 본다. 채점 방식 이름이나 기여한 답을 바꿔도 순위가 같은지 속성으로 고정했다.
- `endTurn`은 차례 값을 버리고 `undefined`를 돌려준다. 라우트가 상태를 비우는 자리와 값이 사라지는 규칙(I-13)을 한 함수에 모았다.
