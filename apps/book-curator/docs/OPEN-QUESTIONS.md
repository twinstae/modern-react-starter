# 사람이 정할 것 / 확인할 것

에이전트가 임의로 정하면 안 되는 것, 또는 사람의 확인이 필요한 것을 모은다. 결정되면
여기서 지우지 말고 "결정됨"과 결정 내용을 남긴다. 티켓 문서와 `SEED-QUESTIONS.md`의
세부 근거를 여기서 가리킨다.

## 결정됨: 운영자 콘솔 단순화 (10월 28일)

- [x] **서랍 = 이름 + 문항 + 책(제목·저자·출판사).** 서랍별 관련도, 핵심 단어, 권하는
      이유, 함께 생각해 볼 질문, 서랍 표시, 서랍별·공통 상태 문장 템플릿, 서랍 순서,
      기준 응답, 선택형 질문, 수량, 질문 세트 초안을 두지 않는다. 아래 절에서 이 항목들에
      걸린 질문은 더 정하지 않아도 된다.
- [x] **책은 서랍 페이지에서 CSV로 올린다.** 한 책은 한 서랍에만 든다.
- [x] **공개는 "지금 서랍으로 공개" 버튼이다.** 점검은 서랍 2개 미만·문항 없는 서랍만
      막고 쏠림·문항 수 차이·책 3권 미만은 경고한다.
- [x] **주인 PIN은 숫자 6자리로 생성한다.** 열쇠를 건넨 뒤 태블릿은 "서랍을 열어
      보세요"만 보이고, 서랍 속 책 화면과 산 책 기록은 없다.
- [ ] **쏠림 범위를 서랍 수에 맞춰 옮긴 값을 확인한다.** 서랍이 N개면 1순위 비율이
      1/N의 0.7~1.26배 안이어야 경고가 없다. 서랍 7개일 때 PRD의 10~18%와 같다.
      시드(서랍 7개, 문항 2개씩)는 첫 서랍 B6가 18.15%로 경고에 걸린다.
- [ ] **운영 DB의 예전 서가·질문 세트를 옮길지 정한다.** 예전 표는 지우지 않고 남겼다.
      새 서랍은 운영자 화면에서 다시 만들고 CSV로 책을 올린다.

## 서가·서랍 운영 (TICKET-00010)

- [ ] **실제 책과 권하는 이유·질문을 채운다.** 지금 화면은 30~50권을 빠르게 넣는 자리만
      만들었다. 어떤 책을 어느 서랍에 둘지, 책마다 이유와 질문을 어떻게 쓸지는 주인이
      정한다. 저장 전에 미리보기나 일괄 등록은 없다.
- [ ] **서랍 표시(`mark`)를 어디서 고칠지 정한다.** 표시는 공개 질문 세트가 소유하므로
      운영 화면에서 직접 고치지 않는다(I-11). TICKET-00011에서 새 질문 세트 버전을
      공개할 때 함께 바꾼다. 급히 바꿔야 하면 새 버전을 공개하는 흐름을 먼저 확인한다.
- [ ] **3종 미만 경고를 얼마나 강하게 할지 정한다.** 지금은 서랍 카드에 경고만 보여
      주고 입력은 막지 않는다. 게이트는 공개·열쇠 건넴을 막고, 주인 확인에도 경고가
      남는다. 저장 자체를 막을지, 경고만 둘지 실제 운영에서 본다.
- [ ] **책 삭제가 필요한지 정한다.** T10은 책 추가·수정만 한다. 서랍에서 빼는 것과
      서가에서 책 자체를 지우는 것은 다르다. 오등록 책을 지울 길이 필요하면 별도
      티켓으로 정한다.

## 질문 세트 운영 (TICKET-00011)

- [ ] **서랍마다 문항을 몇 개 둘지, 문구를 어떻게 쓸지 정한다.** 지금 시드는 7서랍×2문항
      14개다. 관리자 화면에서 문항을 더하고 뺄 수 있지만, 실제 손님이 3분 안에 끝낼지,
      반대 문항을 넣을지는 주인이 정한다. 문구 목록은 [`SEED-QUESTIONS.md`](SEED-QUESTIONS.md).
- [ ] **서랍 표시(`mark`)와 핵심 단어의 최종 값을 정한다.** 표시는 실제 서랍장 번호·열쇠와
      맞춰야 하고, 핵심 단어는 PRD 부록 B를 시드로 넣었다. 관리자 화면에서 고칠 수 있지만
      손님에게 어디까지 보일지는 아직 가정이다.
- [ ] **기준 응답을 관리자가 고칠 수 있게 할지 정한다.** 지금은 읽기 전용 미리보기만 있고,
      문항 구조를 바꾸면 저장할 때 기준 응답이 비워진다. 문항을 고친 뒤 "이렇게 답하면 이
      순위"를 다시 넣으려면 별도 편집기나 안전한 재계산 규칙이 필요하다.
- [ ] **쌓인 응답을 몇 건부터 공개 판단에 쓸지 정한다.** 지금은 표본이 공개를 막고, 쌓인
      응답의 쏠림은 경고다. PRD A-4는 50~100건을 학습·판단의 출발점으로 본다. 그 전에는
      쌓인 응답이 적어 비율이 크게 흔들린다.
- [ ] **선택형 질문 편집기(C-1)를 만들지 정한다.** 스키마와 점검은 선택형을 받지만 이번
      화면은 문항형만 고친다. 복제한 초안에 선택형이 있으면 그대로 보존하고 편집하지 않는다.
- [ ] **공개 게이트를 얼마나 엄격하게 할지 정한다.** 지금은 점검 실패(표본 쏠림, 빈 서랍,
      기준 응답 불일치)와 서가 3종 미만이 공개를 막고, 문항 수 불균형·쌓인 응답 쏠림은
      경고다. 경고도 막을지, 주인이 예외를 둘 수 있게 할지 실제 운영에서 본다.
- [ ] **공개 뒤 손님 차례가 도는 중 새 버전을 공개해도 되는지 확인한다.** 구조상 차례는 시작
      때 받은 묶음으로 끝난다(I-11). 다만 운영자가 손님이 있는 시간에 공개해도 되는지의
      현장 규칙은 정해야 한다.

## 주인 확인과 서랍 속 책 (TICKET-00012)

- [ ] **2순위·다른 서랍에도 열쇠를 줄지 정한다(C-3).** 지금 주인 확인은 추천 서랍과
      모든 서랍에 `열쇠 건넴` 버튼을 둔다. 실제로는 추천 서랍만 열쇠를 주고 나머지는
      주인 재량으로 둘지, 2순위에도 열쇠를 줄지 정한다. 기록은 어느 쪽이든 추천과
      건넨 서랍을 함께 남긴다(R-7).
- [ ] **산 책 기록을 필수로 할지 선택으로 할지 정한다(C-5).** 지금은 책 화면 아래
      작은 칸에서 주인이 원할 때만 누른다. 기록하지 않아도 손님은 책을 가져갈 수 있고,
      기록을 빠뜨리면 수량이 실제와 어긋난다(R-9).
- [ ] **주인 모드의 유휴 제한을 정한다.** 지금은 손님의 90/120초 타이머를 멈추고 10분
      주인 토큰 만료만 쓴다. 주인이 자리를 비웠을 때 화면이 계속 남는 시간과, 다음
      손님이 주인 화면을 보게 되는 위험을 실제 가게에서 본다.
- [ ] **수량 0인 책의 산 책 기록 정책을 정한다.** 지금은 서랍 수량이 0이면 기록 버튼을
      끈다. 수량은 참고값이라 실제 책이 있는데도 0으로 적혀 있을 수 있다(R-9). 0이어도
      기록하게 하고 수량만 0으로 두는 쪽이 나은지 정한다.
- [ ] **주인 확인의 7서랍 배치를 확인한다.** 추천·2순위는 책까지 펼쳐 보이고, 나머지
      서랍은 카드와 "책 N종 · M권 보기" 접기로 둔다. 7서랍을 모두 펼치면 세로 스크롤이
      생기므로, 주인이 몇 초 안에 다른 서랍을 고를 수 있는지 실제 태블릿에서 본다.
      `check:layout`은 이 화면만 스크롤을 허용하고, 고객 화면은 계속 스크롤을 막는다.
- [ ] **주인 확인·서랍 속 책의 실제 문구를 확인한다.** "주인 모드", "열쇠를 건넬 서랍을
      골라 주세요", "이 서랍 열쇠 건넴", "{서랍} 열쇠 건넴", "열쇠를 받았어요",
      "산 책 기록 · 주인만", "이 책 기록", "기록했어요", "처음으로"는 모두 가정한
      문구다. 서가를 서서 보는 주인이 바로 읽을 수 있는지 본다.
