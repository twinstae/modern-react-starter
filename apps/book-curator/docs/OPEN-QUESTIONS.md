# 사람이 정할 것 / 확인할 것

에이전트가 임의로 정하면 안 되는 것, 또는 사람의 확인이 필요한 것을 모은다. 결정되면
여기서 지우지 말고 "결정됨"과 결정 내용을 남긴다. 티켓 문서와 `SEED-QUESTIONS.md`의
세부 근거를 여기서 가리킨다.

## 시드 질문 세트와 점검 (TICKET-00003)

- [ ] **문항 문구 14개를 확정한다.** 지금은 모두 `[가정]` 초안이다. 손님이 태블릿 앞에
      서서 읽어도 바로 이해되는지, 책방 말투와 맞는지 본다. 목록은
      [`SEED-QUESTIONS.md`](SEED-QUESTIONS.md) §1.
- [ ] **서윤 기준 응답을 확정한다.** "B6 1순위, B1 2순위"가 의도인지 확인한다.
- [ ] **서랍당 문항 2개를 유지할지 정한다.** 2개면 14문항으로 짧지만 B6가 17.9%로
      상한(18%)에 붙는다. 3개면 21문항이고 분포는 고르게 퍼진다.
- [ ] **반대 문항을 넣을지 정한다.** 지금은 없다. 동의 편향(R-2)을 줄이려면 서랍마다
      하나씩 두고 기준 응답·점검을 다시 잰다.
- [ ] **동점이 끝까지 갈 때 쓸 서랍 순서를 확인한다.** 지금은 B6, B1, B4, B2, B7, B3, B5.
      표본의 22.65%가 이 규칙까지 간다.
- [ ] **1순위 비율 10~18% 기준을 승인한다.** 코드 상수를 슬쩍 풀지 않고, 바꾸려면
      스펙과 `SEED-QUESTIONS.md`에서 먼저 합의한다.

## 문장과 인용 (TICKET-00004)

- [ ] **상태 문장·인용 문형의 최종 문구를 확인한다.** 지금 기본값은
      "{별명} 님에겐 지금, {서랍}이/가 필요해 보여요", 2순위
      "{서랍}이/가 함께 보이면 좋겠어요", 인용 "‘{문항}’라고 하셨죠"다.
      TICKET-00007 결과 스토리를 주인과 함께 읽고 정한다.
- [ ] **인용은 긍정 기여(값 > 0)만 쓴다.** 0이나 음수 기여뿐인 서랍은 인용을 만들지 않고
      `NoCitationError`로 실패한다. 선택형 가중치에 0·음수를 허용할지, 인용 후보를
      어떻게 둘지 정한다.

## 화면 디자인 (TICKET-00006/00007)

- [ ] **색과 분위기를 확인한다.** 지금은 가게의 초록 간판, 노란 벽, 종이, 빨간 스탬프를
      가져와 `따뜻한 흰 종이 + 초록 버튼 + 노란 띠/첫 화면 패널 + 빨간 서랍 표시`로 쓴다.
      실제 가게 사진을 배경에 쓸지, 지금처럼 색·활자만 쓸지 정한다. 기준은
      `docs/DESIGN.md`.
- [ ] **첫 화면의 노란 패널을 확인한다.** 세로에서는 위 절반, 가로에서는 왼쪽 절반이
      노랑이다. 매장의 노란 벽을 옮긴 것인데, 태블릿 밝기에서 눈이 편한지 본다.
- [ ] **질문 화면의 다섯 칸을 확인한다.** 숫자와 말을 함께 보여 주고, 누르면 바로 다음
      질문으로 간다. 2~4에도 "아니다/보통/그렇다"를 둘지, 양 끝만 글자로 둘지 정한다.
- [ ] **"질문 14개 · 3분쯤 걸려요" 문구를 확인한다.** 실제 문항 수는 질문 세트 데이터에서
      온다. 3분은 가정한 시간이다.

## 서가와 서랍 표시 (TICKET-00005)

- [ ] **서랍 표시(번호·열쇠) 문구를 확인한다.** 지금 시드는 "1번 · 열쇠 1" 같은
      가정값이다. 실제 서랍장의 번호·열쇠와 맞는지, 손님에게 어디까지 보일지 정한다.
- [ ] **서랍 속 책이 3종 미만일 때 운영 화면에서 얼마나 강하게 막을지 정한다.** 지금은
      게이트가 공개를 막고 주인 확인에 경고를 보여 준다. 수량 0인 책은 목록에 남긴다.

## 키오스크 화면 (TICKET-00006)

- [ ] **유휴 기준을 확인한다.** 지금은 90초에 "계속하시겠어요?", 120초에 처음 화면이다.
      태블릿 앞에서 문항을 읽는 시간과 뒤 손님의 대기 시간을 보고 정한다.
- [ ] **글꼴을 확인한다.** 제목은 Noto Serif KR, UI는 Noto Sans KR를 웹폰트로 받는다.
      책방의 인쇄물·간판과 맞는지, 오프라인에서 폰트가 없을 때의 대체 모양도 본다.
- [ ] **질문 화면의 다섯 칸 모양을 확인한다.** 지금은 1·5만 글자로 읽히고 2~4는 숫자로
      보인다. 태블릿 세로·가로 스토리를 실제 기기에서 본다.
- [ ] **TICKET-00007 전까지의 완료 안내 문구를 확인한다.** 결과 화면이 들어오면 지워질
      임시 화면이다.

## 결과 화면 (TICKET-00007)

- [ ] **추천 서랍을 권하는 이유 7개를 확정한다.** 지금 시드는 모두 가정한 초안이고,
      인용("…라고 하셨죠") 뒤에 따로 읽히는 한두 문장이다.
      서랍 코드 순서는 B6, B1, B4, B2, B7, B3, B5다.
  - B6 삶의 방식을 바꾸는 책: "바꾸고 싶은 마음에는 작은 습관부터 건드리는 책이 잘 맞아요."
  - B1 나를 들여다보는 책: "나를 들여다보고 싶은 날에는 천천히 자신에게 말을 거는 책을 권해요."
  - B4 사회를 이해하는 책: "세상이 답답할 때는 그 구조를 함께 들여다보는 책이 좋아요."
  - B2 관계를 다시 생각하는 책: "가까운 사람과의 거리가 고민될 때 관계를 다시 그려 보는 책이 도움이 돼요."
  - B7 잠시 멈춰 생각하는 책: "잠시 멈추고 싶을 때는 곁에 오래 두고 읽는 책이 잘 어울려요."
  - B3 다른 삶을 만나는 책: "다른 삶이 궁금할 때는 내가 모르던 사람의 하루를 만나는 책을 권해요."
  - B5 세계를 넓혀 보는 책: "세계를 넓히고 싶을 때는 역사와 과학을 건너오는 책이 좋아요."
- [ ] **결과 화면의 고정 문구를 확인한다.** 2순위 제목 "함께 보면 좋은 책", 비슷함 한 줄
      "두 서랍이 비슷하게 보여요. 주인과 함께 골라도 좋아요.", 안내
      "이 화면을 책방 주인에게 보여 주세요", 버튼 "주인 확인"·"다시 해 보기"는 모두
      가정한 문구다.
- [ ] **서랍 표시를 손님 결과 화면에 그대로 보여 줄지 확인한다.** 스펙 §5.3은 추천 서랍
      카드에 서랍 표시를 넣는다. 지금 시드는 "1번 · 열쇠 1"이고, 손님에게 보일 최종
      모양(번호만, 열쇠 번호 포함 등)을 정해야 한다. `[가정]` 같은 편집 표시는 데이터에
      넣지 않고 이 문서에만 둔다.
- [ ] **주인 확인 전환을 확인한다.** 지금은 버튼을 누르면 "주인 확인은 다음 단계에서
      연결됩니다"만 보인다. TICKET-00012에서 PIN 잠금으로 바꾼다.

## 익명 이벤트 (TICKET-00008)

- [ ] **태블릿 이름을 정한다.** 기기마다 `VITE_KIOSK_NAME`에 짧은 이름(예: "계산대 옆",
      "창가 자리")을 넣는다. 기본값은 "계산대 옆"이고, 이벤트의 `kioskName`에만 쓰인다.
- [ ] **문항을 순서 기반 ID(`q1`, `q2`…)로 가리킬지 확인한다.** 질문 스키마에 문항 id가
      없어, 이벤트의 `questionId`는 질문 세트 버전 + 순서로 만든다. 문항을 고쳤을 때 같은
      자리를 같은 문항으로 볼지, 나중에 영구 id를 둘지 정한다.

## 운영·인증 (뒤 티켓)

- [ ] 주인 확인을 같은 태블릿 PIN으로 할지, 주인 휴대폰으로 할지 (C-4).
- [ ] 2순위 서랍의 열쇠를 줄지, 주인 재량으로 둘지 (C-3).
- [ ] 산 책 기록을 필수로 할지 선택으로 할지 (C-5).
- [ ] 실제 배포 호스팅의 접근 로그에 IP가 남는지, 얼마나 보존하는지 (TICKET-00008).
