# TICKET-00006: 낙관적 업데이트와 실패 처리

- 스펙: [SPEC-0001](SPEC-0001.md) — User Stories 44–48, 52
- Blocked by: TICKET-00008, TICKET-00003
- Status: done

## 만들 것

제출한 대화, 판정, 캐릭터 변경이 저장을 기다리지 않고 곧바로 화면에 반영된다. 저장되기 전까지는 "저장 중", 저장에 실패하면 "실패"로 표시된다.
같은 세션을 연 다른 탭이 먼저 저장해서 충돌이 나면, 최신 로그를 다시 불러오고 입력하던 내용은 그대로 둔다.
서버 쪽에서는 쓰는 도중 프로세스가 죽어 로그 파일의 마지막 줄이 깨져도 세션을 계속 열 수 있다.

## 알아야 할 것

- **ventyd의 동작:** mutation은 이벤트를 엔티티의 큐에 쌓고 상태에 바로 반영한다. `repository.commit(entity)`가 큐를 어댑터로 보낸다.
  - 따라서 "커밋되지 않은 이벤트" = 큐에 있는 이벤트이고, 화면 상태 = 엔티티 상태 + 커밋된 이벤트 + 큐의 이벤트다.
- **세션 컨트롤러의 책임** (TICKET-00003에서 만든 UI 비의존 모듈을 확장한다)
  - 제출하면 mutation을 바로 적용하고, 그 이벤트를 `pending`으로 표시한 뒤 커밋한다.
  - 성공하면 `pending`이 사라진다.
  - 네트워크 오류 등으로 실패하면 그 이벤트를 `failed`로 표시한다. 자동 재시도는 하지 않는다.
  - 충돌(어댑터의 충돌 예외)이 나면 서버에서 이벤트를 다시 불러와 엔티티를 새로 만든다. 큐의 이벤트는 버리고, 컨테이너에 "충돌로 다시 불러옴"을 알린다.
  - 커밋은 한 번에 하나씩 순서대로 진행한다. 커밋 중에 들어온 제출은 이어서 커밋한다.
- **입력 유지:** 충돌로 버려진 제출의 입력 텍스트는 해당 입력창에 다시 채워 준다. 입력창의 `onSubmit`이 오류를 돌려주는 기존 흐름을 이용한다.
- **실패한 이벤트 표시:** 화면에 남기되 "실패" 표시를 한다. 새로고침하면 사라진다(저장되지 않았으므로). 실패 후 다음 제출 처리는 단순하게 정한다(예: 실패한 큐를 비우고 서버 상태로 다시 불러옴). 정한 내용은 CONTEXT.md나 ADR에 짧게 남긴다.
- **표시용 컴포넌트:** 세션 로그의 `entries`에 `status: "committed" | "pending" | "failed"`를 추가한다. 컴포넌트는 이 값만 보고 표시한다.
- **깨진 마지막 줄:** 파일 이벤트 로그가 읽을 때 마지막 줄을 JSON으로 파싱할 수 없으면 무시하고 경고 로그를 남긴다.
  - 그다음 `append`는 깨진 줄 뒤에 이어 쓰지 않는다. 깨진 줄을 잘라 내거나 새 줄에서 시작해서 파일을 다시 읽을 수 있는 상태로 둔다.
  - 마지막이 아닌 줄이 깨진 경우는 데이터 손상이므로 오류로 처리한다.
- **테스트용 가짜:** 충돌과 실패는 메모리 어댑터를 감싼 가짜로 재현한다. 예: 다음 커밋에서 충돌이나 실패를 던지는 어댑터, 외부에서 다른 탭처럼 이벤트를 끼워 넣을 수 있는 공유 메모리 저장소.

## 작업하며 배운 것

- **ventyd의 `commit`은 큐를 그 자리에서 비우고 어댑터를 동기로 부른다.** 그래서 mutation 직후 곧바로 `commit`을 부르면 묶음마다 `expectedVersion`이 정확하다. 컨트롤러는 저장소를 감싼 `append`에서 저장 전 묶음을 등록하고(`pending`), 저장은 promise 꼬리에 줄 세운다. 이 동기 호출에 기대므로, 제출 직후 `pending`이 보이는 테스트가 이를 지킨다.
- **`submit`은 저장을 기다리지 않는다.** 기다리면 입력창이 비워지기 전에 Enter를 또 누를 수 있고, 그새 쓴 글이 성공 뒤 초기화에 지워진다. 그래서 규칙 위반만 반환값으로 알리고, 저장 중, 실패, 충돌은 스냅샷(`status`, `restored`)으로 알린다. 기다려야 하는 쪽(테스트)을 위해 `idle()`을 둔다.
- **실패한 큐와 충돌의 결정은 CONTEXT.md "저장"에 적었다.** 충돌 때 되돌려 줄 글은 같은 편의 여러 제출을 줄바꿈으로 잇는다. 캐릭터 추가 입력은 되돌려 주지 않는다. 충돌 안내는 입력창이 아니라 페이지 위쪽의 경고 한 곳(`ConflictNotice`, `view.notice`)이다. 캐릭터 추가와 보관이 충돌해도 같은 알림이 뜬다(되돌려 줄 글은 없다). 다음 제출을 받으면 사라진다.
- **저장 줄은 `createSaveQueue`로 떼었다**(`save-queue.ts`). 줄 세우기, 묶음 상태, 멈춤, 충돌과 실패 구분이 여기 있고, 제출과 묶음의 연결은 `run(meta, commit)`이 명시한다. ventyd가 `commit` 안에서 어댑터를 동기로 부른다는 가정은 `ventyd-assumptions.test.ts`가 못 박고, 깨지면 `append`가 `SaveQueueMisuseError`를 던진다.
- **다시 불러오는 동안 줄은 멈춘 채다.** 읽기가 끝난 뒤에야 `resume()`한다. 다시 불러오기가 실패하면 줄은 멈춘 채 묶음을 `failed`로 두고 알림을 띄우며, 다음 제출이 다시 시도한다.
- **가짜 저장소**(`event-log-store.fake.ts`): `hold`/`releaseNext`로 저장을 손으로 풀고, `failNext`로 실패시키며, `otherTab`은 같은 메모리에 직접 쓴다. 처음에는 줄 세우기를 없애도 세 번 연속 테스트가 통과했다(가짜가 FIFO로 풀어 주기 때문). `mostAtOnce`로 동시 저장 수를 재서 테스트가 실제로 줄 세우기를 지키게 했다.
- **파일 로그의 끝 조각 처리는 00003에서 이미 있었다.** 이번에는 줄바꿈으로 끝났는데 JSON이 아닌 마지막 줄과, 중간 줄 손상 오류(처음부터 통과)를 더했다.
- **표시 확인은 접근성 트리로 한다.** 저장 상태는 `role="status"` 글("저장 중", "실패")로 확인한다. 흐림, 점선 테두리 같은 모양은 스토리(`Unsaved`, `PendingRoll`)에서 눈으로 본다.
