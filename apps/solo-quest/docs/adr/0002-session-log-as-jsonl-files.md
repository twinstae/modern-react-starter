# 세션의 이벤트 로그는 DB가 아니라 세션별 JSONL 파일에 추가만 한다

세션은 항상 이벤트 로그 전체를 한 번에 불러오고, 이벤트는 추가만 된다. 그래서 행 단위 질의가 필요 없고, 세션마다 한 줄에 이벤트 하나를 쓰는 JSONL 파일이 DB보다 단순하고 효율적이다.
세션 목록은 질의와 정렬이 필요하므로 DB(drizzle, 개발은 PGlite)에 둔다. 두 저장소는 영속 전략이 다르다.

## Consequences

- DB의 유니크 제약이 없으므로, 버전 연속성은 서버가 세션별 잠금 안에서 검사한다. 서버 프로세스가 하나라고 가정한다.
- 쓰다가 죽어 마지막 줄이 깨질 수 있다. 읽을 때 마지막 줄의 손상은 무시한다.
- 로그 저장소는 인터페이스 뒤에 있다. 여러 서버나 서버리스로 가면 S3 등에 배치로 올리는 구현으로 바꾼다.
- 세션 목록 행을 먼저 만들고 로그 파일은 첫 커밋 때 생긴다. 로그가 비어 있으면 아직 시작되지 않은 세션이다.
