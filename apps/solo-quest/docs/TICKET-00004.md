# TICKET-00004: 주사위 판정

- 스펙: [SPEC-0001](SPEC-0001.md) — User Stories 18–28
- Blocked by: TICKET-00008, TICKET-00003
- Status: done

## 만들 것

어느 입력창에서든 `/r 2d6+1 자물쇠 따기`처럼 치면 주사위가 굴려지고, 그 확정된 결과가 그 편의 판정으로 로그에 기록된다. 판정 항목에는 원래 표기, 주사위 하나하나의 값, 합계, 라벨이 보인다.
잘못된 표기나 처음 보는 명령은 이벤트를 만들지 않는다. 대신 입력창 아래에 오류를 보여 주고, 입력한 내용은 그대로 둔다.

## 알아야 할 것

- **입력 해석:** 순수 함수 `parseInput(text)` → `{ type: "message", content } | { type: "roll", notation, label? } | { type: "error", message }`
  - `/`로 시작하지 않으면 대화다.
  - `/r <표기> [라벨]`이면 판정이다. 표기는 공백 없는 첫 토큰이고, 나머지는 라벨이다(앞뒤 공백 제거, 없으면 생략).
  - 그 밖의 `/명령`은 "알 수 없는 명령" 오류다. `/`로 시작하는 대화를 보내는 방법은 없다.
- **표기 파서:** 순수 함수. 문자열을 항 목록으로 바꾸거나 오류를 낸다.
  - 항은 `NdM`(N을 생략하면 1) 또는 정수 상수이고, 항 사이를 `+`/`-`로 잇는다. 대소문자는 구분하지 않는다.
  - 허용 예: `d20`, `d100`, `2d6+1`, `3d6+2`, `3d6-2+1d4`
  - 거부 예: `2x6`, `d`, `2d`, `0d6`, `2d0`, `2d6+`, 빈 문자열
  - 상한: 주사위 수는 표기 전체에서 100개 이하, 면 수는 1000 이하(초과하면 오류). 상한은 상수로 둔다.
- **굴림:** 순수 함수 `roll(parsed, random)`. `random`은 0 이상 1 미만의 값을 내는 함수로 주입받는다.
  - 결과는 항마다 주사위 값 목록(또는 상수)과 합계다.
  - 실제 앱은 `crypto.getRandomValues` 기반 난수를 넘긴다.
- **이벤트:** `session:dice_rolled { side, as, notation, terms, total, label? }`
  - `terms`는 굴린 결과다. 재생할 때 다시 굴리지 않는다. reducer는 이전 상태를 그대로 돌려준다.
  - 라벨은 1~140자다. 서버 스키마도 같은 규칙으로 검증한다(공유 valibot 스키마).
- **흐름:** 컨테이너가 입력창의 `onSubmit` 텍스트를 `parseInput`으로 해석한다.
  - 판정이면 굴린 결과를 mutation에 넘긴다.
  - 오류면 입력창에 오류를 돌려준다(입력창의 오류 표시와 입력 유지는 TICKET-00003에서 만들었다).
- **표시:** 세션 로그의 판정 항목은 대화 항목과 같은 정렬 규칙(마스터 왼쪽, 플레이어 오른쪽)을 따르고, 화자 이름을 보여 준다.

## 인수 조건

**도메인/단위**

- [x] `parseInput`: 일반 텍스트는 대화, `/r 2d6+1`은 라벨 없는 판정, `/r 2d6+1 자물쇠 따기`는 라벨 있는 판정, `/desc 안개`와 `/r`(표기 없음)은 오류다.
- [x] 표기 파서가 위의 허용 예를 모두 받아들이고 거부 예와 상한 초과를 모두 거부한다(표 기반 테스트).
- [x] 고정된 `random`을 주입하면 `roll`의 주사위 값과 합계가 예상과 정확히 같다. 상수 항과 빼기 항도 반영된다.
- [x] 경계값: `random`이 0이면 각 주사위는 1, 1에 가장 가까우면 면 수가 나온다.
- [x] 판정 mutation을 커밋하고 다시 불러오면 `terms`와 `total`이 같다(다시 굴리지 않는다). 상태(캐릭터 목록)는 바뀌지 않는다.
- [x] 141자 라벨이나 없는 화자로 하는 판정은 이벤트를 만들지 않는다.

**API**

- [x] `dice_rolled` 이벤트를 커밋하고 조회하면 그대로 돌아온다. 141자 라벨은 422다.

**컴포넌트** (스토리 args, props만)

- [x] 세션 로그 스토리에 대화와 판정이 섞인 경우가 있다. 판정 항목에 표기, 주사위별 값, 합계, 라벨이 보이고, 라벨이 없으면 라벨 자리가 없다.
- [x] 마스터 판정은 왼쪽, 플레이어 판정은 오른쪽에 정렬된다. (스타일은 테스트하지 않는다. `Mixed` 스토리에서 눈으로 확인한다.)

## 작업하며 배운 것

- **이벤트를 하나 더하는 일이 정말 한 곳이었다.** `dice_rolled`는 `defineSchema`의 `event`에 적고 변이만 더했다. reducer는 기본 분기가 이전 상태를 돌려줘서 건드리지 않았고, 서버 코드는 한 줄도 바뀌지 않았다. API 테스트(왕복, 141자 라벨 422)는 처음부터 통과했다.
- **모듈 경계.** `parseInput`(`parse-input.ts`)은 표기를 검증하지 않고 잘라내기만 한다. 표기 검증과 굴림은 `dice.ts`(`parseNotation`, `roll`)다. 컨트롤러가 둘을 이어 `parseInput` → `parseNotation` → `roll` → `session.rollDice` 순으로 부른다. 어느 단계의 오류든 문자열로 돌려주므로 입력창은 바뀐 것이 없다.
- **난수는 컨트롤러의 필수 인자다.** `createSessionController({ random })`. 기본값을 두면 숨은 비결정이 생기므로 테스트는 고정 난수를 넘긴다. `crypto.getRandomValues` 기반 난수(`browser-random.ts`)는 `session-client.ts`에서만 만든다. `[0, 1)`을 얻으려고 `Uint32Array / 2**32`를 쓴다.
- **굴린 항의 타입은 valibot 스키마에서 나온다**(`RolledTerm`). 이벤트 본문과 로그 항목이 같은 타입을 쓴다. 굴리기 전 항(`DiceTerm`)은 주사위 개수를 가지고, 굴린 뒤 항은 `values` 목록을 가진다.
- **`LogEntry`는 `kind`로 나뉘는 합집합**(`message | roll`)이다. `SessionLog`는 계속 `entries`만 받는다. 로그 항목 변환은 이벤트마다 같은 `base`(id, 편, 화자 이름, 시각)를 만들고 갈래만 덧붙인다.
- **라벨 자리는 `role="note"`에 `aria-label="판정 라벨"`을 붙여 확인한다.** siheom의 `query.note`는 이름이 필수라서, 라벨이 없을 때 자리 자체가 없음을 `count`로 확인하려면 이름이 필요했다. 정렬은 siheom에 스타일 단언이 없어 `getComputedStyle(...).alignSelf`로 본다.
- **열어 둔 결정.**
  - `/R`처럼 대문자 명령은 알 수 없는 명령이다(표기는 대소문자를 가리지 않는다). 명령은 정확히 `/r`만 받는다.
  - 상수 항은 0 이상 정수다. 표기 첫머리의 `+`나 `-`는 거부한다. 음수 합계는 가능하다(`d4-10`).
  - 입력창의 140자 제한은 `/r 표기 `를 포함한 전체 글에 걸린다. 그래서 140자 라벨을 온전히 쓸 수 없다(라벨 자체의 141자 검사는 도메인 변이가 한다). 입력창이 명령을 알게 하려면 폼 검증을 `parseInput` 뒤로 옮겨야 해서 이번에는 두었다.
- **(작업 방식) vitest browser가 전체 실행에서 한 번 실패했다**(`message-input`의 화자 선택 테스트). 단독 재실행에서는 연속으로 통과했다. 가끔 나는 불안정이니 의심되면 먼저 다시 돌린다.
