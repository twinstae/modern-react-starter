# TICKET-00007: 가상 스크롤 로그

- 스펙: [SPEC-0001](SPEC-0001.md) — User Stories 40–43
- Blocked by: TICKET-00004 (높이가 다른 판정 항목까지 함께 확인하기 위해)
- Status: ready-for-agent

## 만들 것

세션 로그가 수천 개의 기록에서도 부드럽게 스크롤된다.

- 세션을 열면 맨 아래(최신)가 보인다.
- 맨 아래를 보고 있을 때 새 기록이 생기면 따라 내려간다.
- 위쪽 기록을 읽는 중에 새 기록이 생기면 읽던 위치가 그대로 유지된다.

## 알아야 할 것

- **라이브러리:** `@tanstack/react-virtual`(`useVirtualizer`). 항목 높이는 가변이다. 140자 대화의 줄바꿈과 판정 항목 때문이다. `measureElement`로 실제 높이를 측정한다.
- **아래 고정 동작**
  - 처음 렌더링하면 마지막 항목으로 스크롤한다.
  - "맨 아래에 있음"은 스크롤 위치가 바닥에서 작은 임계값 이내인 상태로 정의한다.
    - 그 상태에서 `entries`가 늘어나면 새 마지막 항목으로 스크롤한다.
    - 그렇지 않으면 스크롤 위치를 바꾸지 않는다.
  - 높이 측정이 늦게 끝나 위치가 튀지 않게 한다. 아래 고정 상태라면 측정 뒤에 다시 바닥에 맞춘다.
  - 맨 아래가 아닐 때 새 기록이 오면 "새 기록" 버튼을 보여 줄 수 있다. 이 버튼은 선택 사항이다.
- **컴포넌트 경계:** 세션 로그 컴포넌트는 여전히 `entries` props만 받는다. 가상 스크롤은 이 컴포넌트 내부 구현이며, props 계약(편, 화자 이름, 내용 또는 판정 결과, 시각, status)은 바꾸지 않는다.
  - 기존 세션 로그 스토리와 테스트(0개, 1개, 10개, 판정 혼합, pending/failed)는 그대로 통과해야 한다.
- **많은 데이터 스토리:** 수천 개(예: 5,000개)의 항목을 만드는 스토리 args 생성 함수를 둔다. 대화와 판정, 양쪽 편, 짧은 글과 140자 글, 줄바꿈이 섞이게 한다. 무작위 값은 고정 시드로 만든다.
- **브라우저 테스트에서 스크롤:** 스크롤 컨테이너의 `scrollTop`과 화면에 렌더링된 항목으로 확인한다. 렌더링된 DOM 항목 수가 전체보다 훨씬 적은지(가상화가 동작하는지)도 확인한다.

## 인수 조건

**컴포넌트** (스토리 args, props만)

- [ ] 5,000개 스토리를 렌더링하면 DOM에 렌더링된 항목 수가 전체의 일부(예: 100개 미만)다.
- [ ] 처음 렌더링하면 마지막 항목이 보인다.
- [ ] 맨 아래에 있는 상태에서 `entries`에 항목을 추가하면(props 갱신) 새 마지막 항목이 보인다.
- [ ] 위로 스크롤한 상태에서 항목을 추가하면 보이던 항목이 같은 자리에 그대로 보인다.
- [ ] 0개, 1개, 10개, 판정 혼합, pending/failed 스토리와 기존 테스트가 그대로 통과한다.
