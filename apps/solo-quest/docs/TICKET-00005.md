# TICKET-00005: 캐릭터 추가, 보관, 화자 선택

- 스펙: [SPEC-0001](SPEC-0001.md) — User Stories 29–38
- Blocked by: TICKET-00008, TICKET-00003 (TICKET-00004와 동시에 진행 가능)
- Status: done

## 만들 것

세션 화면에서 이름을 입력해 캐릭터를 추가하고, 더 이상 쓰지 않는 캐릭터는 보관한다.

- 각 입력창에서 활성 캐릭터 중 하나를 화자로 고르고, 그 캐릭터의 이름으로 대화하거나 판정한다.
- 캐릭터는 편에 묶이지 않는다. 마스터 입력창에서 NPC로 말해도 된다.
- 보관한 캐릭터는 화자 목록에서 사라지지만, 지난 로그에는 이름이 그대로 남는다.

## 알아야 할 것

- **이벤트**
  - `session:character_added { characterId, name }` → 상태에 활성 캐릭터를 추가한다.
  - `session:character_archived { characterId }` → 그 캐릭터를 `archived: true`로 바꾼다.
  - 상태는 캐릭터 목록 `{ id, name, archived, isDefault }[]`다. 다음 세션이 넘겨받을 유일한 상태이므로, 이 두 이벤트가 상태를 바꾸는 유일한 이벤트다(`started` 제외).
- **규칙** (mutation이 검사한다)
  - 이름은 앞뒤 공백을 뺀 1~140자다.
  - 활성 캐릭터와 이름이 같으면 추가할 수 없다. 보관된 캐릭터와 이름이 같은 것은 허용한다.
  - 이름은 바꿀 수 없다(바꾸는 이벤트가 없다).
  - 기본 캐릭터(`isDefault`)는 보관할 수 없다. 이미 보관된 캐릭터를 다시 보관하는 것도 오류다.
  - 보관된 캐릭터를 화자로 하는 대화나 판정은 오류다(TICKET-00003/00004의 "활성 캐릭터" 규칙이 그대로 적용된다).
- **화자 선택 상태:** 입력창마다 선택된 화자 id는 화면 상태다(이벤트가 아니다).
  - 기본값은 마스터 쪽이 `GM`, 플레이어 쪽이 `Player`다.
  - 선택된 캐릭터가 보관되면 그 입력창의 화자는 그 편의 기본 캐릭터로 돌아간다.
- **로그의 화자 이름:** 지난 기록의 이름은 보관 여부와 상관없이 캐릭터 id로 상태에서 찾는다. 보관해도 상태에서 지워지지 않으므로 찾을 수 있다.
- **표시용 컴포넌트** (props만)
  - 캐릭터 패널: `characters`(활성/보관 구분), `onAdd({ name })`, `onArchive(characterId)`. 기본 캐릭터에는 보관 버튼이 없다.
    - `onAdd`가 오류(예: 이름 중복)를 돌려주면 입력을 유지하고 오류를 보여 준다.
  - 입력창의 화자 선택: TICKET-00003의 `characters`, `speakerId`, `onSpeakerChange` props를 쓴다. 목록에는 활성 캐릭터만 나온다.
  - select나 combobox 같은 컴포넌트가 `@repo/ui`에 없으면 `@repo/ui`에 추가한다. 레시피, 스토리, 기존 ui 컴포넌트 형식을 따른다.

## 인수 조건

**도메인/단위**

- [x] 캐릭터를 추가하면 상태에 활성 캐릭터로 나타나고, 보관하면 `archived`가 된다. 커밋하고 다시 불러와도 같다.
- [x] 활성 캐릭터와 같은 이름은 거부되고, 보관된 캐릭터와 같은 이름은 허용된다.
- [x] 빈 이름, 141자 이름은 거부된다.
- [x] 기본 캐릭터 보관, 없는 캐릭터 보관, 이미 보관된 캐릭터 보관은 거부된다.
- [x] 보관된 캐릭터를 화자로 하는 대화와 판정은 거부된다.

**API**

- [x] `character_added`/`character_archived` 이벤트를 커밋하고 조회하면 그대로 돌아온다. 141자 이름은 422다.

**컴포넌트** (스토리 args, props만)

- [x] 캐릭터 패널 스토리가 기본 캐릭터만 있는 경우, 1개 추가, 10개, 보관된 캐릭터가 섞인 경우를 보여 준다. 기본 캐릭터에는 보관 버튼이 없다.
- [x] 이름을 넣고 제출하면 `onAdd`에 `{ name }`이 넘어간다. `onAdd`가 오류를 돌려주면 입력이 남고 오류가 보인다.
- [x] 보관 버튼을 누르면 `onArchive`에 그 캐릭터 id가 넘어간다.
- [x] 입력창 화자 목록에는 활성 캐릭터만 나오고, 다른 화자를 고르면 `onSpeakerChange`에 그 id가 넘어간다.
- [x] 세션 로그 스토리에서 보관된 캐릭터의 지난 기록에도 이름이 보인다.

## 작업하며 배운 것

- **이벤트 둘과 규칙은 계획대로 `Session`의 mutation에 들어갔다.** reducer는 `character_added`/`character_archived` 둘만 상태를 바꾼다. 이름 규칙은 `ShortText`를 이벤트 본문에도 걸어 서버가 141자 이름을 422로 막는다. 활성 캐릭터와 같은 이름만 거부하고(`trim` 뒤 정확히 같은 글자, 대소문자 구분), 보관된 캐릭터와 같은 이름은 허용한다.
- **캐릭터 id는 mutation 안에서 `uuidv7()`로 만든다.** 컨트롤러에 id 생성기를 새로 주입하지 않았다. 대신 테스트는 추가한 캐릭터를 이름으로 찾는다(`characterNamed`). id를 고정해야 할 일이 생기면 그때 주입한다.
- **"보관된 화자 거부"는 새 코드가 아니었다.** 00003에서 만든 `#assertActiveSpeaker`가 이미 막고 있어서, 보관이 생긴 뒤의 테스트가 첫 실행에 통과했다. 규칙 완화 변이를 넣어 테스트가 실패하는 것을 확인했다.
- **로그 항목에 `speakerId`를 더하고 묶음을 `side + speakerId`로 가른다.** 보관된 캐릭터와 같은 이름의 새 캐릭터가 이어 말하면 이름만 비교하는 묶음은 둘을 합쳐 버린다. 로그 변환은 화자 이름을 `character_added`에서도 모은다(없으면 id가 그대로 나왔다).
- **입력창 인터페이스는 바뀐 대로 시험했다.** 티켓의 `speakerId`/`onSpeakerChange`는 쓰지 않았다. 화자는 폼이 들고 있으므로 "활성 캐릭터만 목록에 나오고 고른 id로 제출된다"를 `onSubmit` 값으로 확인한다. 입력창은 전체 캐릭터를 받아 활성만 낸다(`activeCharacters`).
- **"고른 화자가 보관되면 기본 화자로 돌아간다"는 폼 안에서 바로잡는다.** `@repo/ui`에 `useSimpleField(name)`(값을 읽고 바꾸는 hook)을 더했고, 입력창 안의 `SpeakerFallback`이 고른 id가 활성 목록에 없으면 편의 기본 화자로 되돌린다. 쓰던 글은 그대로 남는다. 앱이 react-hook-form에 직접 의존하지 않게 하려고 hook을 `@repo/ui`에 두었다.
- **`SimpleInput`에도 `hideLabel`을 더했다**(`SimpleTextarea`, `SimpleSelect`와 같은 방식). 캐릭터 이름 입력은 자리 표시 글자만 보이고 접근성 이름은 "캐릭터 이름"이다. 이 옵션 자체를 시험하는 테스트는 따로 없고 패널 테스트가 이름으로 입력을 찾는다.
- **캐릭터 패널은 제목 줄 옆의 접이식이다.** 닫혀 있으면 "캐릭터 n" 버튼 하나만 자리를 차지하고, 열면 그 아래에 겹쳐 떠서(absolute, 최대 높이 60dvh에 스크롤) 로그와 입력창을 밀어내지 않는다. 활성 캐릭터가 위, 보관된 캐릭터가 작고 흐리게 아래에 있고, 보관된 캐릭터에는 버튼이 없다. 기본 캐릭터에도 보관 버튼이 없다.
- **`onArchive`도 오류 메시지를 돌려주게 했다**(`Promise<string | undefined>`). 티켓에는 없던 결정이다. 충돌처럼 보관이 실패했을 때 조용히 삼키지 않으려고 패널이 오류를 보여 주고, 다음에 성공하면 지운다. 컨트롤러의 `addCharacter`/`archiveCharacter`는 `submit`처럼 오류 메시지 또는 `undefined`를 돌려준다. 커밋과 오류 처리는 `commit` 하나로 모았다.
- **siheom 0.3.0은 여전히 부재를 확인하지 못한다.** 보관 버튼이 없음, 보관된 캐릭터가 화자 목록에 없음은 `runSiheom`을 나누고 `screen.queryByRole`로 확인했다. 오류가 사라지는 것은 `waitFor`로 기다렸다.
- **(작업 방식) 첫 실행에 통과한 테스트는 `test:` 커밋으로 남기고, 구현을 일부러 깨 실패하는 것을 확인했다.** 해당 커밋: 빈/141자 이름, 보관된 이름 재사용, 보관된 화자와 편 무관 화자, API 왕복, 컨트롤러 오류 경로, 로그의 보관된 캐릭터 이름, 패널의 추가 오류와 10개 스토리.
- **(작업 방식) 선택 메뉴 테스트는 글을 먼저 쓰고 화자를 나중에 고른다.** 옵션을 고른 뒤 `assertions.not.expanded`를 기다려도 그 뒤의 `fill`이 가끔 사라져(전체 실행에서 자주) 테스트가 흔들렸다. `not.expanded`만으로는 부족하다. 화자를 고르는 테스트는 `fill`을 먼저 하고, 고른 뒤에는 입력하지 않는다.
