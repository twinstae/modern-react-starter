# TICKET-00005: 캐릭터 추가, 보관, 화자 선택

- 스펙: [SPEC-0001](SPEC-0001.md) — User Stories 29–38
- Blocked by: TICKET-00003 (TICKET-00004와 동시에 진행 가능)
- Status: ready-for-agent

## 만들 것

세션 화면에서 이름을 입력해 캐릭터를 추가하고, 더 이상 쓰지 않는 캐릭터는 보관한다.

- 각 입력창에서 활성 캐릭터 중 하나를 화자로 고르고, 그 캐릭터의 이름으로 대화하거나 판정한다.
- 캐릭터는 편에 묶이지 않는다. 마스터 입력창에서 NPC로 말해도 된다.
- 보관한 캐릭터는 화자 목록에서 사라지지만, 지난 로그에는 이름이 그대로 남는다.

## 알아야 할 것

- **이벤트**
  - `session:character_added { characterId, name }` → 상태에 활성 캐릭터를 추가한다.
  - `session:character_archived { characterId }` → 그 캐릭터를 `archived: true`로 바꾼다.
  - 상태는 캐릭터 목록 `{ id, name, archived, isDefault }[]`다. 다음 세션이 넘겨받을 유일한 상태이므로, 이 두 이벤트가 상태를 바꾸는 유일한 이벤트다(`started` 제외).
- **규칙** (mutation이 검사한다)
  - 이름은 앞뒤 공백을 뺀 1~140자다.
  - 활성 캐릭터와 이름이 같으면 추가할 수 없다. 보관된 캐릭터와 이름이 같은 것은 허용한다.
  - 이름은 바꿀 수 없다(바꾸는 이벤트가 없다).
  - 기본 캐릭터(`isDefault`)는 보관할 수 없다. 이미 보관된 캐릭터를 다시 보관하는 것도 오류다.
  - 보관된 캐릭터를 화자로 하는 대화나 판정은 오류다(TICKET-00003/00004의 "활성 캐릭터" 규칙이 그대로 적용된다).
- **화자 선택 상태:** 입력창마다 선택된 화자 id는 화면 상태다(이벤트가 아니다).
  - 기본값은 마스터 쪽이 `GM`, 플레이어 쪽이 `Player`다.
  - 선택된 캐릭터가 보관되면 그 입력창의 화자는 그 편의 기본 캐릭터로 돌아간다.
- **로그의 화자 이름:** 지난 기록의 이름은 보관 여부와 상관없이 캐릭터 id로 상태에서 찾는다. 보관해도 상태에서 지워지지 않으므로 찾을 수 있다.
- **표시용 컴포넌트** (props만)
  - 캐릭터 패널: `characters`(활성/보관 구분), `onAdd({ name })`, `onArchive(characterId)`. 기본 캐릭터에는 보관 버튼이 없다.
    - `onAdd`가 오류(예: 이름 중복)를 돌려주면 입력을 유지하고 오류를 보여 준다.
  - 입력창의 화자 선택: TICKET-00003의 `characters`, `speakerId`, `onSpeakerChange` props를 쓴다. 목록에는 활성 캐릭터만 나온다.
  - select나 combobox 같은 컴포넌트가 `@repo/ui`에 없으면 `@repo/ui`에 추가한다. 레시피, 스토리, 기존 ui 컴포넌트 형식을 따른다.

## 인수 조건

**도메인/단위**

- [ ] 캐릭터를 추가하면 상태에 활성 캐릭터로 나타나고, 보관하면 `archived`가 된다. 커밋하고 다시 불러와도 같다.
- [ ] 활성 캐릭터와 같은 이름은 거부되고, 보관된 캐릭터와 같은 이름은 허용된다.
- [ ] 빈 이름, 141자 이름은 거부된다.
- [ ] 기본 캐릭터 보관, 없는 캐릭터 보관, 이미 보관된 캐릭터 보관은 거부된다.
- [ ] 보관된 캐릭터를 화자로 하는 대화와 판정은 거부된다.

**API**

- [ ] `character_added`/`character_archived` 이벤트를 커밋하고 조회하면 그대로 돌아온다. 141자 이름은 422다.

**컴포넌트** (스토리 args, props만)

- [ ] 캐릭터 패널 스토리가 기본 캐릭터만 있는 경우, 1개 추가, 10개, 보관된 캐릭터가 섞인 경우를 보여 준다. 기본 캐릭터에는 보관 버튼이 없다.
- [ ] 이름을 넣고 제출하면 `onAdd`에 `{ name }`이 넘어간다. `onAdd`가 오류를 돌려주면 입력이 남고 오류가 보인다.
- [ ] 보관 버튼을 누르면 `onArchive`에 그 캐릭터 id가 넘어간다.
- [ ] 입력창 화자 목록에는 활성 캐릭터만 나오고, 다른 화자를 고르면 `onSpeakerChange`에 그 id가 넘어간다.
- [ ] 세션 로그 스토리에서 보관된 캐릭터의 지난 기록에도 이름이 보인다.

**직접 확인**

- [ ] `bun run dev`에서 캐릭터 "경비병"을 추가하고 마스터 입력창에서 경비병으로 말한다. 경비병을 보관하면 마스터 화자가 `GM`으로 돌아가고, 지난 기록에는 "경비병"이 남는다.
