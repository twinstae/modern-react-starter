## 만들 것

자주 쓰는 판정을 **매크로**로 등록하고, 입력창 위의 버튼으로 굴린다.
버튼을 누르면 매크로의 **빈칸**(예: 능력치, 난이도)마다 고르는 칸이 있는 폼이 뜨고, 제출하면 빈칸을 채운 표기로 그 입력창의 편과 화자로 굴린다.
굴린 결과에는 매크로의 **결과 이름**과 **눈 효과**가 붙는다.

```
Ironsworn  d6+{능력치:1..4}+{수정치:0..4} max10 > 2d10 => 0 실패 | 1 약한 성공 | 2 강한 성공
Cypher     d20 >= {난이도:0..10}*3 => ..-1 실패 | 0.. 성공 ; 20 큰 이득, 19 작은 이득, 1 마스터 개입
겁스       3d6 <= {기술:3..20} => ..-10 대실패 | -9..-1 실패 | 0.. 성공 ; 3..4 !대성공, 17 !실패, 18 !대실패
Fate       4dF+{기술:0..5} >= {상대:0..8} => ..-1 실패 | 0 동점 | 1..2 성공 | 3.. 멋진 성공
던전월드   2d6+{능력치:-1..3} => ..6 실패 | 7..9 약한 성공 | 10.. 강한 성공
```

## 알아야 할 것

- **매크로 식:** `<표기 틀>[ => <범위> <이름> | ...][ ; <범위> [!]<이름>, ...]`
  - 표기 틀은 판정 표기(TICKET-00009)에 빈칸 `{이름:최소..최대}`를 넣은 것이다. 최소, 최대는 정수(음수 가능)이고 최소 ≤ 최대다.
    빈칸 이름은 매크로 안에서 겹치지 않는다. 고를 수 있는 값은 100개까지다.
  - 빈칸을 채울 때 `+-1`은 `-1`, `--1`은 `+1`로 적는다. 기록되는 표기는 채운 표기다(`2d6-1`, `d20 >= 3*3`).
  - 범위는 `a`, `a..b`, `..b`, `a..`이고 범위끼리 겹치지 않는다.
  - `=>` 뒤는 **결과 값**의 범위마다 붙인 **결과 이름**이다. 결과 값에 맞는 범위가 없으면 이름이 붙지 않는다.
  - `;` 뒤는 **눈**의 범위마다 붙인 **눈 효과**다. 결과 이름 옆에 붙고, `!`가 붙으면 결과 이름을 그 이름으로 바꾼다.
  - 이름은 짧은 글이다. 이름에 `|`, `,`, `;`는 쓸 수 없다.
  - 등록할 때 빈칸을 모두 최솟값으로, 모두 최댓값으로 채운 표기가 올바른지 확인한다.
  - 겁스의 기술에 따른 대성공(5, 6)과 대실패(17), Cypher의 노력·자산·기술은 넣지 않는다. 기록된 눈과 차이를 보고 말로 처리한다.
- **세션 상태:** 매크로는 캐릭터처럼 세션 상태다. `{ id, name, definition }`
  - 이벤트: `session:macro_added { macroId, name, definition }`, `session:macro_removed { macroId }`
  - 이름은 짧은 글이고 매크로끼리 겹치지 않는다. 식이 올바르지 않으면 규칙 위반이다.
  - 넘겨받은 상태는 아직 기본 캐릭터만 넘긴다. 다음 세션이 매크로를 넘겨받는 것은 세션 이어 하기 때 정한다.
- **굴림:** 컨트롤러 `rollMacro({ side, as, macroId, values, label? })`
  - 라벨을 비우면 매크로 이름이 라벨이다.
  - `session:dice_rolled`에 선택 필드 `outcome`(최종 결과 이름), `effect`(바꾸지 않은 눈 효과)를 더해 남긴다. 나중에 매크로를 지워도 기록은 그대로다.
- **화면**
  - 헤더의 매크로 패널(캐릭터 패널과 같은 형식): 목록, 삭제, 이름과 매크로 식으로 등록
  - 입력창마다 매크로 버튼. 누르면 Popover에 빈칸마다 Select, 라벨, "굴리기"가 있다. 화자는 입력창에서 고른 화자다.
  - 매크로 폼은 입력창 폼 안(React 트리)에 Portal로 뜬다. React 이벤트는 Portal을 지나 바깥 폼까지 올라가므로,
    `SimpleForm`이 제출 이벤트 전파를 멈춰 안쪽 폼 제출이 바깥 폼을 제출하지 않게 한다(`@repo/ui` 쪽 고침).

## 작업하며 배운 것

- **`SimpleForm` 고침은 실제 버그를 잡았다.** Portal 안의 폼을 제출하자 바깥 폼도 제출됐다(테스트로 확인). 입력창 테스트는 대화를 쳐 둔 채 매크로를 굴린다. 대화가 비어 있으면 바깥 폼이 검증에서 막혀, 고침이 없어도 테스트가 통과하기 때문이다. 고침을 되돌리면 실패하는 것을 확인했다.
- **Ark UI `Select`는 `Popover` 안에서도 그대로 동작한다.** 옵션 Portal을 눌러도 Popover가 닫히지 않았다.
- **매크로 폼의 필드 이름은 빈칸 이름이 아니라 순서(`slot0`)다.** react-hook-form은 필드 이름의 `.`과 `[]`를 경로로 읽는다.
- **siheom `fill`은 user-event 키보드 문법이라 `{`, `[`를 특수 키로 읽는다.** 매크로 식을 칠 때는 `{{`, `[[`로 바꿔 넘긴다(`macro-panel.test.tsx`의 `literal`). 여러 곳에서 필요해지면 siheom에 글자 그대로 넣는 동작을 제안할 만하다.
- **다섯 시스템의 매크로 식은 `macro.fixture.ts` 하나에 있다.** 도메인 테스트와 스토리가 함께 쓴다.
- **매크로 식은 세션 상태에 글 그대로 두고 굴릴 때마다 읽는다.** 읽은 결과(빈칸, 범위)를 이벤트에 넣지 않아, 문법을 바꿔도 이벤트 스키마는 그대로다.
- **(작업 방식) 기계 부하가 높을 때(load average 12) PGlite 테스트가 15초 제한을 넘기고 브라우저 연결이 끊겼다.** 따로 돌리면 8.8초에 통과한다. 부하가 내려간 뒤 CI를 다시 돌렸다.
- **사용자가 화면에서 두 가지를 찾았다.** 매크로 패널이 잘렸고(Popover 폭이 `xs`로 고정), 매크로 폼 안의 Select 목록이 Popover에 가려졌다(Select `dropdown` 1000 < Popover `popover` 1500).
  - 테스트는 둘 다 놓쳤다. siheom 기본 `runSiheom`의 클릭은 가려진 요소도 누른다. `@repo/ui`의 Popover 테스트처럼 실제 입력(`createReactSiheom({ user: userEvent })`)으로 누르면 가려진 옵션을 누르지 못해 실패한다. 이 방식으로 실패하는 테스트를 먼저 만들었다.
  - 고침은 z-index를 쓰지 않는다(사용자 결정). 떠 있는 층은 DOM 순서로 쌓인다. Select와 Dialog는 열 때 body 끝에 붙고 닫으면 떨어진다(`lazyMount`, `unmountOnExit` 기본값). Popover는 열 때 그리면 Ark가 제목을 못 찾아 `aria-labelledby`가 빠지므로 미리 그려 둔다.
  - 폭은 Popover 레시피의 `size` variant(`sm` 기본, `md`)로 고른다. 앱에서 폭을 덮어쓰지 않는다.
- **(작업 방식) CI 중 Chromium이 메모리 부족으로 죽은 적이 있다.** 메모리 6.8GB 기계에서 다른 세션과 함께 돌 때였고, 부하가 내려간 뒤에는 통과했다.
