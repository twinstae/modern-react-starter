# SPEC-0001: SOLO QUEST 프로토타입 — 세션 하나에서 대화와 판정

- 상태: ready-for-agent
- 출처: [docs/SOLO_QUEST.md](../../../docs/SOLO_QUEST.md) 기획, 2026-10-07 grilling 합의

## Problem Statement

나는 혼자 TRPG를 한다. 마스터(세계)의 묘사와 플레이어의 대사를 번갈아 치고, 주사위를 굴려 판정한다.
지금은 이 기록이 메모장, 주사위 앱, 종이 시트에 흩어져 있다. 누가(어느 편에서, 어떤 캐릭터로) 무엇을 말했고
무엇을 굴려 어떤 결과가 나왔는지가 하나의 시간순 기록으로 남지 않는다.
나중에 시트, 매크로, 내보내기, 세션 이어 하기를 붙이려면 그 바탕이 되는 기록 — 확정된 사실만 쌓이는 이벤트 로그 — 가 먼저 있어야 한다.

## Solution

브라우저에서 세션을 만들고 연다. 세션 화면에는 이벤트 로그 하나와 입력창 두 개가 있다.
왼쪽 입력창에 치면 **마스터** 편으로, 오른쪽에 치면 **플레이어** 편으로 기록되고, 로그에서도 마스터는 왼쪽, 플레이어는 오른쪽에 정렬된다.
각 입력창에서 **화자**(캐릭터)를 고르고, 일반 텍스트를 치면 대화가, `/r 2d6+1 자물쇠 따기`처럼 치면 주사위 판정이 기록된다.
캐릭터는 이름만 있고, 추가하거나 보관할 수 있다. 기록은 지울 수 없다.
로그는 아무리 길어도 부드럽게 스크롤되고, 제출한 내용은 저장을 기다리지 않고 곧바로 보인다.

## User Stories

### 세션 목록

1. 플레이어로서, 세션 목록에서 지금까지 만든 세션을 제목과 만든 시각으로 보고 싶다. 하던 세션을 다시 찾을 수 있도록.
2. 플레이어로서, 제목을 입력해 새 세션을 만들고 싶다. 새 플레이를 시작할 수 있도록.
3. 플레이어로서, 목록에서 세션을 눌러 세션 화면으로 들어가고 싶다. 이어서 플레이할 수 있도록.
4. 플레이어로서, 세션 목록이 최근에 만든 순서로 정렬되기를 원한다. 최근 세션을 바로 찾을 수 있도록.
5. 플레이어로서, 제목이 비어 있거나 140자를 넘으면 세션을 만들 수 없기를 원한다. 목록이 읽을 수 있는 상태로 유지되도록.

### 세션 시작

6. 플레이어로서, 새 세션에 처음 들어가면 `GM`과 `Player` 두 기본 캐릭터가 이미 있기를 원한다. 바로 말할 수 있도록.
7. 플레이어로서, 세션을 만든 직후 시작이 중간에 실패했더라도 다시 열면 정상적으로 시작되기를 원한다. 망가진 세션이 남지 않도록.
8. 플레이어로서, 마스터 입력창의 기본 화자는 `GM`, 플레이어 입력창의 기본 화자는 `Player`이기를 원한다. 매번 고르지 않아도 되도록.

### 대화

9. 플레이어로서, 왼쪽 입력창에 텍스트를 치고 제출하면 마스터 편 대화로 기록되기를 원한다. 세계의 묘사를 남길 수 있도록.
10. 플레이어로서, 오른쪽 입력창에 텍스트를 치고 제출하면 플레이어 편 대화로 기록되기를 원한다. 내 캐릭터의 행동과 말을 남길 수 있도록.
11. 플레이어로서, 마스터 편 기록은 로그 왼쪽에, 플레이어 편 기록은 오른쪽에 정렬되기를 원한다. 누가 말했는지 한눈에 구분되도록.
12. 플레이어로서, 각 기록에 화자 이름이 보이기를 원한다. 어떤 캐릭터의 말인지 알 수 있도록.
13. 플레이어로서, 대화가 140자를 넘으면 제출할 수 없기를 원한다. 기록이 짧고 리듬감 있게 유지되도록.
14. 플레이어로서, 남은 글자 수를 입력 중에 보고 싶다. 제출 전에 140자 제한을 알 수 있도록.
15. 플레이어로서, 빈 입력은 제출되지 않기를 원한다. 실수로 빈 기록이 남지 않도록.
16. 플레이어로서, 줄바꿈이 기록에 그대로 보이기를 원한다. 짧은 시나 대사를 끊어 쓸 수 있도록.
17. 플레이어로서, 기록이 일반 텍스트로만 보이기를 원한다(마크다운 해석 없음). 친 그대로 남도록.

### 주사위 판정

18. 플레이어로서, 입력창에 `/r 2d6+1`을 치면 주사위가 굴려지고 결과가 기록되기를 원한다. 키보드만으로 판정할 수 있도록.
19. 플레이어로서, `/r 2d6+1 자물쇠 따기`처럼 표기 뒤에 라벨을 붙이고 싶다. 무엇을 위한 판정인지 남도록.
20. 플레이어로서, `d20`, `d100`, `3d6+2`, `3d6-2+1d4`처럼 `NdM`과 상수를 더하고 빼는 표기를 쓰고 싶다. 흔한 판정을 모두 할 수 있도록.
21. 플레이어로서, 판정 기록에 원래 표기, 주사위 하나하나의 값, 합계가 보이기를 원한다. 결과를 검증할 수 있도록.
22. 플레이어로서, 판정도 대화처럼 입력한 편(마스터/플레이어)과 화자를 가지기를 원한다. 누가 굴렸는지 알 수 있도록.
23. 플레이어로서, 판정 결과가 한번 기록되면 다시 계산되거나 바뀌지 않기를 원한다. 주사위 결과는 확정된 사실이므로.
24. 플레이어로서, 잘못된 표기(`/r 2x6`)를 치면 이벤트가 만들어지지 않고 입력창 아래에 오류가 보이기를 원한다. 무엇이 틀렸는지 알고 고칠 수 있도록.
25. 플레이어로서, 오류가 났을 때 입력한 내용이 지워지지 않기를 원한다. 조금만 고쳐 다시 제출할 수 있도록.
26. 플레이어로서, 아직 없는 명령(`/desc` 등)을 치면 알 수 없는 명령이라는 오류를 보고 싶다. 대화로 잘못 기록되지 않도록.
27. 플레이어로서, 라벨도 140자를 넘을 수 없기를 원한다. 모든 텍스트가 같은 규칙을 따르도록.
28. 플레이어로서, 비현실적으로 큰 표기(예: 주사위 수천 개)는 거부되기를 원한다. 실수로 화면이 망가지지 않도록.

### 캐릭터

29. 플레이어로서, 이름을 입력해 캐릭터를 추가하고 싶다. NPC나 내 캐릭터의 이름으로 말할 수 있도록.
30. 플레이어로서, 각 입력창에서 활성 캐릭터 중 하나를 화자로 고르고 싶다. 그 캐릭터의 말로 기록되도록.
31. 플레이어로서, 어느 편 입력창에서든 어떤 캐릭터든 고를 수 있기를 원한다. 예를 들어 마스터 편에서 NPC로 말할 수 있도록.
32. 플레이어로서, 더 이상 등장하지 않는 캐릭터를 보관하고 싶다. 화자 목록이 깔끔하게 유지되도록.
33. 플레이어로서, 보관한 캐릭터가 화자 목록에서는 사라지지만 지난 기록에는 이름이 그대로 보이기를 원한다. 과거 기록이 바뀌지 않도록.
34. 플레이어로서, 기본 캐릭터 `GM`과 `Player`는 보관할 수 없기를 원한다. 말할 캐릭터가 하나도 없는 상태가 되지 않도록.
35. 플레이어로서, 활성 캐릭터와 같은 이름의 캐릭터는 추가할 수 없기를 원한다. 화자를 헷갈리지 않도록.
36. 플레이어로서, 보관된 캐릭터와 같은 이름의 새 캐릭터는 추가할 수 있기를 원한다. 이름을 다시 쓸 수 있도록.
37. 플레이어로서, 캐릭터 이름이 비어 있거나 140자를 넘으면 추가할 수 없기를 원한다.
38. 플레이어로서, 보관된 캐릭터를 화자로 골라 둔 상태라면 그 입력창의 화자가 기본 캐릭터로 돌아가기를 원한다. 보관된 캐릭터로 기록되지 않도록.

### 기록의 불변성

39. 플레이어로서, 기록을 수정하거나 지울 수 없기를 원한다. 로그가 실제로 일어난 일의 기록으로 남도록.

### 긴 로그와 반응성

40. 플레이어로서, 세션을 열면 전체 로그가 보이고 맨 아래(최신)에 스크롤이 가 있기를 원한다. 바로 이어서 플레이할 수 있도록.
41. 플레이어로서, 기록이 수천 개여도 스크롤이 부드럽기를 원한다. 긴 캠페인도 한 세션에서 할 수 있도록.
42. 플레이어로서, 맨 아래를 보고 있을 때 새 기록이 생기면 따라 내려가기를 원한다. 최신 기록을 놓치지 않도록.
43. 플레이어로서, 위쪽 기록을 읽는 중에 새 기록이 생겨도 스크롤 위치가 튀지 않기를 원한다. 읽던 곳을 잃지 않도록.
44. 플레이어로서, 제출한 기록이 저장을 기다리지 않고 바로 로그에 보이기를 원한다. 플레이 흐름이 끊기지 않도록.
45. 플레이어로서, 아직 저장되지 않은 기록에는 "저장 중" 표시가 보이기를 원한다. 무엇이 확정되었는지 알 수 있도록.
46. 플레이어로서, 저장에 실패하면 그 사실이 보이기를 원한다. 기록이 사라졌다고 착각하지 않도록.

### 동시성

47. 플레이어로서, 같은 세션을 두 탭에서 열어 한쪽이 먼저 저장했다면, 다른 탭에서 제출할 때 최신 로그를 다시 불러오기를 원한다. 기록이 엉키지 않도록.
48. 플레이어로서, 그렇게 다시 불러올 때 입력하던 내용이 입력창에 남아 있기를 원한다. 다시 제출할 수 있도록.

### 운영자(개발자)

49. 개발자로서, 서버가 받은 이벤트가 스키마에 맞지 않으면 거부되기를 원한다. 잘못된 이벤트가 로그에 들어가지 않도록.
50. 개발자로서, 서버가 버전이 끊기거나 겹치는 커밋을 거부하기를 원한다. 이벤트 누락과 중복이 생기지 않도록.
51. 개발자로서, 세션 로그가 세션마다 사람이 읽을 수 있는 JSONL 파일로 남기를 원한다. 문제가 생기면 직접 열어 볼 수 있도록.
52. 개발자로서, 쓰는 도중 서버가 죽어 마지막 줄이 깨져도 세션을 계속 열 수 있기를 원한다. 한 줄 때문에 세션 전체를 잃지 않도록.
53. 개발자로서, 로그 저장 방식이 인터페이스 뒤에 있기를 원한다. 나중에 S3 배치 업로드나 브라우저 로컬 저장으로 바꿀 수 있도록.
54. 개발자로서, 도메인 로직이 브라우저에서 돌고 서버는 저장만 하기를 원한다. 같은 도메인 코드가 나중에 오프라인에서도 그대로 돌도록.

## Implementation Decisions

### 앱

- 새 앱 `@repo/solo-quest`를 추가한다. TanStack Start(SPA), `@repo/ui` 디자인 시스템, demo와 같은 테스트 설정(vitest browser + node 프로젝트)을 따른다.
- 도메인, 서버, 화면을 한 앱에 둔다. 브라우저와 서버가 같은 도메인 모듈을 공유한다. 다른 소비자가 생기면 그때 패키지로 분리한다.

### 도메인 (ventyd)

- 세션 하나가 ventyd 엔티티 하나다(엔티티 이름 `session`, 엔티티 id = 세션 id). valibot 통합(`ventyd/valibot`)으로 스키마를 정의한다.
- 이벤트(본문):
  - `session:started { characters: Character[] }` — 넘겨받은 상태. 지금은 항상 기본 캐릭터 `GM`, `Player`.
  - `session:character_added { characterId, name }`
  - `session:character_archived { characterId }`
  - `session:message_posted { side, as, content }`
  - `session:dice_rolled { side, as, notation, terms, total, label? }`
- `side`는 `"master" | "player"`, `as`는 캐릭터 id.
- 상태는 **캐릭터 목록**뿐이다(`{ id, name, archived, isDefault }`). 대화와 판정 이벤트의 reducer는 이전 상태를 그대로 돌려준다.
  로그 화면은 상태가 아니라 이벤트 목록 자체를 읽는다. 다음 세션이 넘겨받을 것은 이 상태(캐릭터 목록)뿐이고 이벤트 로그는 넘겨받지 않는다.
- 불변 규칙은 엔티티의 mutation이 검사한다(브라우저):
  - 대화 내용, 라벨, 캐릭터 이름, 세션 제목은 1~140자.
  - 화자는 활성(보관되지 않은) 캐릭터여야 한다.
  - 활성 캐릭터끼리는 이름이 겹칠 수 없다. 이름은 바꿀 수 없다.
  - 기본 캐릭터는 보관할 수 없다.
- 이벤트 시각(`eventCreatedAt`)은 현실 시간 Instant(ISO 문자열)다. 이야기 속 시간은 기록하지 않는다.
- id는 ventyd `generateId`로 주입한다(시간순 정렬 가능한 id 권장).

### 주사위

- 순수 함수 둘로 나눈다.
  - 표기 파서: 문자열 → 항(`NdM`, 상수)의 목록 또는 오류. 허용: `NdM`(N 생략 시 1)과 정수 상수를 `+`/`-`로 잇는 표기, 공백 허용. 주사위 개수와 면 수에 상한을 둔다.
  - 굴림: 파싱된 표기 + 주입된 난수 생성기 → 주사위별 값과 합계.
- 굴림은 reducer 바깥(mutation 호출 전)에서 일어나고, 이벤트에는 확정된 결과만 담는다. 재생해도 다시 굴리지 않는다. 비밀 굴림은 없다.

### 입력 명령

- 순수 함수 `parseInput(text)` → `message | roll | error`.
  - `/`로 시작하지 않으면 대화.
  - `/r <표기> [라벨]`이면 판정.
  - 그 밖의 `/명령`, 잘못된 표기는 오류. 오류는 이벤트를 만들지 않고, 입력창 내용을 유지한 채 아래에 보여 준다.
- `/`로 시작하는 대화를 보내는 방법(이스케이프)은 지금은 없다. 나중에 매크로와 `/desc` 같은 명령이 같은 파서를 확장한다.

### 클라이언트 (브라우저)

- ventyd repository를 브라우저에서 만들고, 어댑터만 바꿔 끼운다. 지금 어댑터는 eden 클라이언트로 서버 이벤트 API를 부르는 HTTP 어댑터다.
  테스트와 Storybook은 같은 인터페이스의 메모리 어댑터를 쓴다(`vi.mock` 금지 규칙에 따라 주입한다).
- 세션 화면은 세션 하나에 대한 "세션 컨트롤러"를 쓴다. 컨트롤러는 불러오기, 제출(대화/판정/캐릭터), 커밋 상태(저장 중/실패), 충돌 처리를 맡는 UI 비의존 모듈이다.
- 화면 컴포넌트는 표시용이다. 세션 목록, 로그, 입력창, 캐릭터 패널은 값과 콜백을 props로만 받는다. 라우트(컨테이너)가 query와 컨트롤러를 컴포넌트에 연결한다.
- 입력창은 `onSubmit({ side, as, text })`를 부른다. 콜백이 오류를 돌려주면 입력을 유지하고 오류를 보여 주며, 성공하면 입력을 비운다. 텍스트를 명령으로 해석(`parseInput`)하는 것은 컨테이너 쪽이다.
- 낙관적 업데이트: 제출하면 mutation이 이벤트를 큐에 쌓고 화면에 바로 반영한다. 커밋되지 않은 이벤트는 "저장 중", 커밋이 실패하면 "실패"로 표시한다.
- 충돌(버전 불일치): 최신 이벤트를 다시 불러와 엔티티를 다시 만들고, 입력창 내용은 유지한다. 자동 재시도와 탭 간 실시간 동기화는 하지 않는다.
- 로그가 비어 있으면 아직 시작되지 않은 세션으로 보고, 컨트롤러가 `session:started`부터 커밋한다.
- 로그 화면은 `@tanstack/react-virtual`로 만든 아래 고정 가상 목록이다. 높이가 가변적인 항목, 맨 아래에 있을 때만 따라 내려가기, 위를 읽는 중 위치 유지를 처음부터 지원한다. 세션 전체 이벤트를 한 번에 불러온다.
- 서버 상태(세션 목록, 세션 이벤트 불러오기)는 TanStack Query로 다룬다.

### 서버 (elysia + eden)

- elysia 앱을 TanStack Start 서버 라우트에 붙이고, 브라우저는 eden treaty로 타입 안전하게 부른다.
- 서버는 도메인을 실행하지 않는다. 검증은 두 가지뿐이다.
  - 이벤트가 공유 valibot 스키마를 통과하는가.
  - 버전이 끊기지 않는가(`expectedVersion` == 저장된 마지막 버전, 새 이벤트 버전이 1씩 증가).
- API:
  - 세션 목록 조회, 세션 만들기(제목) → 세션 id
  - 세션 이벤트 조회(전체)
  - 세션 이벤트 커밋(`expectedVersion`, 이벤트 목록) → 성공 / 버전 충돌 / 검증 실패
- 세션 목록 저장소: drizzle 테이블 `(id, title, createdAt)`. 개발과 테스트는 PGlite, 운영은 postgres. 세션을 만들면 행을 먼저 만들고, 로그 파일은 첫 커밋 때 생긴다.
- 세션 로그 저장소(이벤트 로그): 인터페이스(`read(sessionId)`, `append(sessionId, expectedVersion, events)`) 뒤에 숨긴다. 지금 구현은 파일이다.
  - 세션마다 JSONL 파일 하나에 한 줄에 이벤트 하나를 추가만 한다.
  - 세션마다 메모리 잠금을 건다. 서버 프로세스가 하나라고 가정한다.
  - 한 커밋은 `write` 호출 하나로 쓴다. fsync는 하지 않는다.
  - 읽을 때 마지막 줄이 깨져 있으면 무시하고 경고한다.
  - 저장 디렉터리는 설정으로 주입한다(기본 `.data/sessions`, 테스트는 임시 디렉터리).

### 디자인 시스템

- 화면은 `@repo/ui` 컴포넌트와 레시피를 쓴다. 필요한 컴포넌트(예: 화자 선택용 select)가 없으면 앱이 아니라 `@repo/ui`에 추가하는 것을 원칙으로 한다.

## Testing Decisions

좋은 테스트는 외부에서 관찰되는 행동만 확인한다. 내부 함수 호출이나 컴포넌트 구조가 아니라 반환값, 커밋된 이벤트, HTTP 응답, 화면에 보이는 것, 콜백에 넘어간 값을 본다.
`vi.mock`/`vi.fn`/`spyOn`은 lint로 금지되어 있다. 의존성은 주입하고, 호출 기록이 필요하면 값을 변수에 기록하는 평범한 함수를 넘긴다.

테스트는 네 단계로 나눈다. 지금은 E2E를 제외한 세 단계에 집중한다.

1. **도메인/단위 테스트** (node)
   - 대상: 세션 엔티티(ventyd), reducer, 표기 파서, 굴림(고정 난수 주입), `parseInput`, 세션 컨트롤러(낙관적 커밋, 충돌 처리).
   - 엔티티와 컨트롤러는 ventyd 메모리 어댑터를 주입해 확인한다. 충돌은 버전이 어긋나면 예외를 던지는 메모리 어댑터로 재현한다.
   - 저장소 구현(JSONL 파일 이벤트 로그, drizzle 세션 목록)은 저장소 인터페이스의 **계약 테스트**로 확인한다. 같은 테스트를 메모리 구현과 실제 구현(임시 디렉터리, PGlite)에 모두 돌린다.
2. **API 테스트** (node) — 영속성에 무지하다.
   - elysia 앱에 저장소 인터페이스의 메모리 구현을 주입하고 HTTP 요청(`app.handle`)으로 확인한다. 파일, DB, 디렉터리를 모른다.
   - 세션 만들기와 조회, 이벤트 커밋과 조회 왕복, 버전 충돌, 스키마 위반.
   - eden 클라이언트를 앱에 직접 연결해 HTTP 어댑터가 ventyd 어댑터 계약을 지키는지도 여기서 확인한다.
3. **컴포넌트 테스트** (browser) — API와 서버 상태에 무지하다.
   - 컴포넌트는 표시할 값과 콜백을 props로만 받는다. 메모리 어댑터, query client, eden을 쓰지 않는다.
   - 모든 컴포넌트는 Storybook 스토리를 갖고, 테스트는 스토리의 args로 렌더링한다(`@siheom/react`의 `runSiheom`).
   - 목록은 0개, 1개, 10개, 매우 많음(수천 개)을 보여 주는 방식을 확인한다.
   - 폼은 제출하면 `onSubmit` 콜백에 올바른 값이 넘어가는지, 콜백이 오류를 돌려주면 어떻게 보여 주는지 확인한다.
4. **E2E 테스트** — 백엔드와 프런트를 합쳐 실행한다. **이번 스펙에서는 범위 밖**이다.
   - 라우트(컨테이너)가 query, 컨트롤러, eden을 컴포넌트에 연결하는 부분은 E2E가 생기기 전까지 `bun run dev`로 직접 확인한다.

참고할 기존 테스트: `@repo/ui`의 `ExampleForm` 테스트(스토리 args로 렌더링, `runSiheom`의 given/actions/assertions), demo의 `standard-schema` 단위 테스트.

## Out of Scope

- 세션 종료(`session:ended`), 세션 종료 스냅샷 저장, 이전 세션을 이어받는 새 세션(캠페인)
- 캐릭터 시트(사용자가 정의하는 HTML과 상태), 애셋, 화이트보드
- 매크로, `/desc` 같은 추가 명령, 마크다운
- 페이트 주사위, 높은 값 유지(`kh`), d66 등 확장 표기, 비밀 굴림
- 기록의 수정과 삭제
- 시간 여행과 재생 화면
- 탭 간 실시간 동기화, 자동 재시도, 멀티플레이
- 로그인과 사용자 구분(better-auth)
- 오프라인 브라우저 저장소 어댑터, S3 배치 업로드
- 서버의 도메인 재생 검증과 정합성 점검 도구
- LLM 마스터
- 내보내기(소설, 비주얼 노벨), 도전과제와 카드
