## 만들 것

주사위를 굴려 무작위 결과를 얻는 **오라클** 표를 앱에 더한다. 표는 세션에 묶이지 않고 어느 세션에서나
찾아 쓰고, 표 형태로 더하고 고칠 수 있다. 자주 쓰는 표는 **세션마다 매크로 버튼으로 등록**해 입력창에서 굴린다.

```
행동        d100   1 꾸민다 | 2 맞붙는다 | ... | 100 불러낸다
장소        d100   1 은신처 | ... | 53–54 절벽 | ... | 100 이상 현상
도전 등급   d100   1–20 성가신 | 21–55 위험한 | 56–80 막강한 | 81–93 극한 | 94–00 서사
날씨        d6     1–3 맑음 | 4–6 폭풍
```

테스트로 Ironsworn 한국어 오라클 **19개**(`oracles-action-to-trouble.md` 9개 + `oracles-role-to-rank.md` 10개)를
시드로 넣는다.

## 알아야 할 것

- **오라클(도메인):** `{ id, name, sides, description?, rows: { min, max, result }[] }`.
  - `sides`는 주사위 면. 기본 100이고 10, 20, 6도 쓴다(2~1000).
  - 표는 **1부터 `sides`까지 빈틈이나 겹침 없이** 덮어야 한다. 구간의 양 끝을 포함한다(`53–54`는 `{min: 53, max: 54}`).
  - `parseOracle`이 이름(짧은 글), 주사위 면, 결과 글(1~500자), 덮음/겹침을 확인한다. 결과는 140자를 넘을 수 있다.
  - `rollOracle(oracle, random)`이 눈 하나(`1..sides`)를 굴려 그 눈이 드는 줄의 결과를 돌려준다.
- **저장:** 전역이라 세션 로그와 따로 둔다. 서버가 `.data/oracles.json`에 `{ version: 1, oracles }`로 쓴다.
  - `OracleStore`(`list`/`save`/`remove`) 뒤에 숨긴다. 파일이 없으면 시드(`src/data/oracle-seed.ts`)로 한 번 쓴다.
  - 쓰기는 임시 파일에 쓰고 바꿔 끼운다. 망가진 파일은 조용히 덮어쓰지 않고 오류로 알린다.
  - API: `GET /oracles`, `PUT /oracles/:id`, `DELETE /oracles/:id`. 규칙 위반은 422와 이유, 없는 id 삭제는 204.
- **시드:** 두 마크다운에서 한 번 옮겨 `src/data/oracle-seed.ts`에 담았다. 여러 열이거나 여러 표인 오라클은
  같은 눈의 결과를 `" / "`로 이어 한 줄로 만들었다(예: `다른 이름`은 거인/바루/트롤 세 열, `철의 땅 사람 이름`은 두 표).
  `정착지 이름`은 구간마다 예시 표가 따로라, 구간 설명과 예시를 한 줄에 적었다.
- **세션:** 표는 전역이지만 **등록만 세션 상태**다.
  - 이벤트: `session:oracle_macro_added { macroId, oracleId }`, `session:oracle_macro_removed { macroId }`,
    `session:oracle_rolled { side, as, oracleId, oracleName, sides, value, result }`.
  - 같은 오라클을 한 세션에 두 번 등록할 수 없다. 굴림 기록은 표를 지우거나 고쳐도 그대로 남는다(이름과 결과를 담는다).
  - 상태는 `oracleMacros: { id, oracleId }[]`다. 표 자체는 넘겨받지 않는다.
- **컨트롤러:** `rollOracle({ side, as, oracleId })`(굴림은 여기서 일어나고 확정된 값만 이벤트로 간다),
  `addOracleMacro({ oracleId })`, `removeOracleMacro(macroId)`. 전역 표는 `OracleSource`로 주입받는다.
- **화면**
  - 헤더의 **오라클 패널**(매크로/캐릭터 패널과 같은 형식): 이름으로 검색, `굴리기`(편과 화자를 골라 그 세션 기록으로 남긴다),
    `매크로 등록/해제`, `편집`, `삭제`, `새 오라클`.
  - **편집 창**: 이름, 주사위, 설명과 줄마다 시작·끝·결과를 표로 고친다. 저장 전에 `parseOracle`로 확인한다.
  - 입력창마다 등록한 오라클 버튼(`OracleButton`). 누르면 그 입력창의 편과 화자로 곧바로 굴린다(빈칸이 없다).
    전역 표가 지워졌으면 `없는 오라클` 버튼으로 보이고 눌리지 않는다.
  - 로그에는 `행동 d100 · 53 절벽`처럼 오라클 이름, 주사위와 눈, 결과가 이어진다.

## 작업하며 배운 것

- **여러 열/여러 표인 오라클은 `" / "`로 이어 한 줄로 만들었다.** 모델을 열 단위로 두면 편집 화면이 복잡해진다.
  같은 눈의 결과를 이어 두면 d100 하나로 표를 다 쓸 수 있고, 편집기도 한 줄에 글 하나만 다루면 된다.
- **마크다운 파서가 표 머리글을 결과로 삼켰다.** `| d100 | Result |`의 `Result`가 예시로 들어가 한 번 걸러야 했다.
- **`styled(Input, ...)`은 쓸 수 없다.** `Input`은 이미 레시피(cva)로 만든 컴포넌트라 "Cannot merge cva with recipe"로 죽는다.
  너비는 `Input`을 감싸는 칸(`styled("div")`)이 정한다.
- **`<input type="number">`는 textbox가 아니라 spinbutton이다.** 컴포넌트 테스트에서 범위 입력을 찾을 때
  `query.spinbutton`을 써야 하고, a11y 스냅샷에는 spinbutton 줄이 잘 보이지 않아 처음에는 표가 비어 보였다.
- **`@repo/ui`에 `Dialog`가 export되어 있지 않았다.** 스토리에서만 쓰던 것을 `ui/index.ts`에 더해 앱에서도 쓴다.
- **(작업 방식) 전체 테스트를 처음 돌릴 때 Vite가 의존성을 다시 최적화하며 브라우저 테스트 파일 import가 한꺼번에 실패했다.**
  다시 돌리니 352개가 모두 통과했다. 새 `@repo/ui` export를 쓴 뒤 첫 실행에서만 나왔다.
