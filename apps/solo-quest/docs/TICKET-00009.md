# TICKET-00009: 비교 판정과 Fate 주사위

- 스펙: 없음. 2026-10-17 대화에서 합의(Ironsworn, Cypher, 겁스, Fate, 던전월드를 한 문법으로)
- Blocked by: TICKET-00004
- Status: in-progress

## 만들 것

판정 표기가 Fate 주사위(`4dF`)와 **비교 판정**을 받는다.

| 시스템 | 표기 | 결과 값 |
|---|---|---|
| Ironsworn | `/r d6+2+1 max10 > 2d10 정찰` | 도전 주사위를 이긴 개수. 액션 6, [5, 7] → `X O` |
| Cypher | `/r d20 >= 9 자물쇠` | 차이. 9가 나오면 `O +0` |
| 겁스 | `/r 3d6 <= 12 자물쇠` | 차이. 10이 나오면 `O +2` |
| Fate | `/r 4dF+3 >= 2 설득` | 차이. [+, 0, -, +] → 4, `O +2` |
| 던전월드 | `/r 2d6+1 정찰` | 액션 점수(지금과 같다) |

결과 이름(강한 성공 등)과 눈 효과(큰 이득 등)는 매크로가 붙인다(TICKET-00010).

## 알아야 할 것

- **문법:** `<액션 표기>[ max<N>][ <비교> <목표>]`
  - 액션 표기는 지금 표기에 `NdF`를 더한 것이다(N을 생략하면 1). Fate 주사위는 -1, 0, +1이 같은 확률로 나온다.
  - 비교는 `>`, `>=`, `<`, `<=`다.
  - 목표는 `NdM` 하나(도전 주사위)이거나, 0 이상의 정수 또는 정수의 곱(`3*3`, 목표치)이다. 그 밖(`2d10+1`, `d10*2`, `4dF`)은 오류다.
  - `max<N>`은 액션 점수의 상한이다. 생략할 수 있고, 비교 없이는 쓸 수 없다.
  - `max`, `d`, `F`는 대소문자를 가리지 않는다. 낱말 사이는 공백 하나 이상이다. 주사위 수 상한은 목표의 주사위까지 센다.
- **입력 해석:** `/r` 뒤 첫 토큰이 표기의 시작이다. 뒤따르는 `max<N>` 토큰과 `<비교> <목표>` 두 토큰까지 표기에 넣고, 나머지는 라벨이다.
  표기는 공백 하나로 이어 붙인 글(`d6+2+1 max10 > 2d10`)로 넘긴다.
- **판정 값(순수 함수 `judgeRoll`)**
  - 액션 점수 = min(합계, 상한)
  - 도전 주사위: 주사위마다 비교해 이기고 진다. 결과 값은 이긴 개수다. 둘 이상이 모두 같으면 Match다.
  - 목표치: 결과 값은 차이다(`>`, `>=`는 점수 − 목표치, `<`, `<=`는 목표치 − 점수). 비교가 맞으면 성공이다.
  - 비교가 없으면 결과 값은 액션 점수다.
  - 눈 = 액션 쪽 주사위 값만 더한 것(상수 제외, 빼는 항은 뺀다). 매크로의 눈 효과가 쓴다.
- **이벤트:** 새 이벤트를 만들지 않고 `session:dice_rolled`에 선택 필드를 더한다. 이전 판정 이벤트는 그대로 유효하다.
  - `terms`에 Fate 항 `{ type: "fate", sign, values }`가 생긴다.
  - `check { op, cap?, against }`. `against`는 `{ type: "dice", sides, values } | { type: "number", value }`다.
  - `terms`, `total`은 액션 쪽(상한 적용 전 합계)이다. 액션 점수, 결과 값, 성공, Match는 저장하지 않고 `judgeRoll`로 계산한다.
  - `outcome`, `effect`(결과 이름, 눈 효과)는 TICKET-00010에서 더한다.
- **표시:** `라벨 표기 · [3] + 2 + 1 = 6 > [5, 7] X O`, `d20 >= 9 · [12] = 12 O +3`
  - Fate 주사위는 `[+, 0, -, +]`로 보인다.
  - 상한에 걸리면 `= 13 → 10`. Match면 "Match". 도전 주사위의 `X O`는 진 것을 앞에 둔다.
